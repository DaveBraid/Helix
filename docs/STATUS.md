## 本轮目标

- 让用户在正常设置区明确完成“API 读取连接 → 当前 Vault 写入验证 → 自动同步”的启用流程；未完成合同验证时，任务页仍按本地 Markdown 正确展示 Stage 状态。
- 非目标：不运行真实滴答合同、不启用远端项目投影、不修改正式 Vault、不发布新版本。

## 当前事实

- Project／Stage Markdown 是项目身份、状态、正文与本地任务的权威源；专用 Canvas 是关系和布局的权威源。
- `2.1.1` 是当前正式版；日常开发只在 `dev`，只有用户明确要求发布时才允许合入 `main`。
- Stage `# 计划行动`进入任务页并形成本地任务树；父任务完成状态由直属子任务派生。
- 含顶层行动的 Stage 都会按 Markdown 状态生成本地父任务；远端父任务存在时复用其精确 ID 和 `Helix Projects` 清单，未绑定时使用本地稳定 ID。
- 滴答 API 口令只建立读取连接；生产写入还要求当前 Vault 中保存的合同能力缓存与当前授权绑定、合同版本一致。
- 正常设置区现直接展示“启用滴答写入”或“滴答写入已就绪”；开发测试折叠区复用同一合同运行入口。
- 自动同步开启但合同能力未完成时只允许读取，并显示远端写入保持只读的明确通知。
- 自动同步在测试 Vault 中仍为关闭状态；本轮没有访问任何滴答远端。

## 相关约束

- 权威边界、本地任务投影与滴答合同见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 3、5 节。
- 写入验证仍只操作唯一标记的专用临时对象；结果未知或清理未证实时保持只读，禁止触碰既有滴答数据。
- 本地 Stage 父任务只是任务页即时投影，不得写入 `data.json`，也不得伪造远端 ID 或 `Helix Projects` 归属。
- API 口令只存 SecretStorage；能力缓存只保存不可逆授权绑定。换 Vault、换授权或合同版本变化均需重新验证。
- 用户 Markdown／Canvas 禁止静默覆盖；本轮正式 Vault 仅做过只读诊断，没有写入。
