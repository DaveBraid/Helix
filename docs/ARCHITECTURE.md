# 架构与边界

本文件定义 Helix 的长期架构、权威数据边界、核心数据流和必须显式处理的边界情况。实现发生结构变化时更新本文件；日常进度不写在这里。

## 1. 权威数据边界

| 数据 | 权威端 | Helix 行为 |
| --- | --- | --- |
| 普通任务、远端清单 | 滴答清单 | 缓存、编辑、离线排队、显式冲突合并 |
| 项目计划行动与本地子任务 | 所属 Stage Markdown | 自动进入 Helix 任务视图；CAS 编辑，不在 `data.json` 保存影子任务 |
| 习惯定义与打卡 | 滴答清单 | 可在 Helix 新建、编辑和打卡，远端记录为最终事实 |
| 专注记录 | 滴答清单 | 导入各设备记录，Helix 计时完成后回写 |
| 项目身份、名称、状态、颜色与正文 | 项目 Markdown | `planned/active/completed/paused/terminated`；Helix 安全写入 |
| 阶段身份、所属项目、状态与正文 | 阶段 Markdown | `idea/active/completed/paused/terminated`、稳定展示编号；支持多个 `active` 阶段 |
| 滴答任务与 Helix 项目/阶段的关联 | Task Reference Markdown | 每个已确认远端任务至多一份关联；项目 0..1、阶段 0..n |
| 日周月年复盘 | Helix Markdown | 模板生成、数据辅助、用户回答 |
| 阶段关系与布局 | 唯一主 Canvas | 只解释明确托管的推进、分支、合并边并强制 DAG |
| “正在进行” | Helix | 不写入滴答标签；首页显示前三项并可展开 |
| 统计、XP、成就、挑战 | Helix 事件账本派生 | 不以可变累计值作为唯一事实 |

## 2. 模块结构

- `src/integrations/dida`：HTTP、能力探测、正规化及任务/项目/习惯/专注适配器。
- `src/sync`：Base 快照、离线操作、三方差异、冲突解决、写前复查与写后验证。
- `src/domain`：项目、阶段、复盘、Canvas DAG、事件、分析、XP 与挑战。
- `src/storage`：SecretStorage、插件持久状态、Markdown/Canvas 安全读写。
- `src/ui`：Obsidian ItemView 和界面组件，只调用服务接口。

## 3. 同步状态机

滴答能力必须按发布门禁分层，禁止用一个总开关同时代表不同风险：

- `DIDA_READ_AVAILABLE`：只允许远端读取、缓存发布与自动只读拉取。
- `DIDA_TASK_WRITE_AVAILABLE`：普通清单／任务写入、离线队列消费与冲突应用；关闭时 `sync()` 必须强制 pull-only，既有待写队列保持原状态。
- `DIDA_CONTRACT_TEST_AVAILABLE`：仅允许专用临时对象合同及其残留收口，不得借此开放生产写入。
- `PROJECT_DIDA_PROJECTION_AVAILABLE`：项目投影；只能在读取与普通写入同时开放后启用。

门禁必须同时覆盖命令、设置、视图和服务网络入口；服务层是最终安全边界。测试可以显式注入能力，发布产物必须由 `release:check` 校验实际常量。

每个远端对象维护：

- Base：上次已验证同步版本，含数据、`etag`、修改时间和正规化 SHA-256 哈希。
- Local：Helix 当前本地版本。
- Remote：本轮同步新拉取版本。

规则：

1. 仅一端相对 Base 变化时可以自动同步。
2. 两端都变化且结果不同，暂停整个对象并建立冲突；即使变化发生在不同字段，也必须由用户确认后提交。
3. 用户逐字段选择本地、远端或自定义值。任务的开始时间、截止时间、时区和全天状态是一组语义字段：界面不得因用户选择其中一项而替其他字段批量选择；合并后的整体必须在任何移动、创建或更新请求前通过校验，非法组合明确拒绝，不得静默折叠。
4. 提交前重新拉取远端；若再次变化，保留仍适用的选择并重开冲突。
5. 提交后重新拉取验证；只有验证成功才更新 Base、Local 并删除队列项。
6. 删除与修改、完成与重开、项目迁移、检查事项和重复规则属于高风险冲突。
7. 应用冲突前必须持久原子认领为 `applying`，同一进程使用按冲突 ID 单飞；`applying` 期间禁止修改字段选择。远端结果未知时保持锁定，只有用户明确确认远端未发生写入后才能人工解锁，禁止重复创建。

## 4. 离线与恢复

- `data.json` 当前 schema 为 2。schema 1 升级时先用确切旧哈希验证快照，再换算 SHA-256；旧事件按语义生成新 ID 并去重，旧挑战领取补齐冻结规则。无法验证的旧数据进入只读恢复，不会被迁移“洗白”。
- 队列持久化且按数组中的持久位置保持同一对象的因果顺序；时间戳相同也不得越序。
- 队列只有一个活动消费者；所有状态转换基于存储中的最新队列原子修改，读取必须等待既有写链完成。
- 插件实例使用单调数据代际和跨重载全局写链：旧实例已开始的保存先完成，新实例再读取；代际失效后的旧保存一律拒绝。卸载后远端请求可以自然返回，但不得再持久化或通知 UI。
- 同一对象的冲突只冻结该对象；其他对象继续同步。
- 可安全合并连续更新，但不能越过创建、移动、完成或删除的因果边界。
- 创建请求超时后进入“待核对”，通过远端查询确认是否已创建；不得直接重试。
- 任何写操作在 `running` 状态中断，重启后都进入人工核对；远端删除后选择本地重建时，必须迁移新 ID、后续队列及 Helix 本地引用。
- 冲突选择删除后，主 Base/Local 缓存删除对应键；后续排队操作可使用只允许出现在队列 Base 中的 tombstone 作为因果基线，并保留任务清单上下文。
- 冲突写回停在 `applying` 时提供两个互斥人工路径：确认未写入后解锁重试；或复读远端并验证与已选结果一致后采纳。重建产生新 ID 时必须显式提供该 ID。
- 401、403、429、永久 4xx、5xx、网络错误和格式异常分别处理。
- 当前任务拉取使用全局过滤接口覆盖收集箱与开放任务，并补取近期已完成任务；仅当本轮声明的覆盖范围全部成功时，才在该范围内推断远端删除。未证实的分页能力不得写成“完整覆盖”。
- 自动同步是显式选择且默认关闭。仅在已配置口令并开启时，插件启动或保存新口令后立即异步拉取一次，再注册周期定时器；关闭时保存口令、重载插件和无关设置保存均不得制造远端读取。并发同步共享同一个在途 Promise，调用方不得在真实拉取完成前收到伪成功。
- 普通任务的连接生命周期为内部 `unknown／online／offline` 三态：启动时 unknown 仍允许首次请求，只有只读同步或连接探测返回明确的 transient 网络故障才进入 offline；401／403、限流、协议或永久错误不得伪装成离线。offline 时创建、更新、完成、重开、删除及清单写入只持久化既有队列且零远端发送；下一次完整同步成功先切回 online，再由唯一消费者安全消费队列。
- 同步核心成功条件只有清单列表、开放任务和近期已完成任务均返回有效数组。单个清单详情只用于证明该清单的远端删除覆盖，失败时保留旧对象且不得阻断核心快照；习惯、打卡或专注失败时保留上次缓存并发布可见警告，也不得使清单与任务整批回滚。
- 演示数据只允许在“无口令、无任何真实滴答缓存且用户开启演示选项”时出现。有口令但未完成首次拉取必须显示等待或失败状态；有真实缓存但离线必须继续显示离线缓存，不能用演示数据覆盖。
- 设置页的“只读拉取测试”在排他远端访问门内执行，只调用读取语义接口并更新本地快照，绝不消费离线队列。普通任务写入、口令切换和合同测试在它结束前均不得取得远端访问权。
- “清除滴答本地缓存”同样只在排他门内操作本地存储：清除可重建的清单、任务、看板、习惯、专注及对应正在进行引用，保留口令、合同能力和事件账本，且零远端请求。存在队列、未决冲突、合同清理、投影清理／分栏 checkpoint 或已启用项目同步时必须拒绝，不能丢失三方合并基线。
- 写入合同版本 12 以本轮唯一标记创建两个临时清单及专用任务，启动前冻结既有清单 ID；删除只接受精确 ID、标记、归属和集合复读均匹配的测试对象。任务清理未获证明时禁止删除任何测试清单，合同运行期间普通远端写入和口令变更冻结。临时清单按 `list→kanban→list` 写后复读，每次写前核对上一步视图基线，并在看板态始终创建一个唯一标记分栏，由详情与分栏端点双源精确复读。基础 CRUD、提醒、重复、检查项、真实父子任务、看板归栏、任务重开与分栏创建分别探测；随后在同一唯一清单与清理计划内复用正式项目同步编排器，验证项目父任务和 Stage 行动子任务的创建、属性更新、完成、重开与删除闭环，并用额外唯一任务验证生产 `OfflineQueue→queueDrain→写后收据` 的创建、更新、完成、重开与删除闭环。合同专用队列探针只在合同排他锁内临时开放，不改变发布门禁；创建结果未知先标记存在未登记对象，删除结果未知先把清理任务标为 `sent-unknown`，均禁止重发。任务详情端点在删除后可能短暂返回旧对象，因此删除证明与生产路径一致，以目标清单开放任务集合中的精确 ID 不存在为准。`projectProjectionVerified` 只在该闭环及最终零残留清理全部通过后成立，并与其他能力一起绑定当前授权；测试未完成或存在任何残留时不得发布。跨清单移动只发送一次，若目标精确复读与来源集合不存在性不能共同证明唯一位置，则记录任务 ID、标记和候选清单进入人工清理保持，禁止自动清理上层清单。
- 检查项探测是独立可选能力：结果未知时绝不领养重生成 ID、绝不重发。只有按精确任务 ID、清单归属和本轮标记删除临时父任务，并证明其在全部候选集合中不存在后，合同才可把 `items` 保持只读并用全新对象继续验证普通 CRUD、看板与重开；清理不能证明则全局中止。不得因检查项失败抹掉已经独立证明的普通任务能力。
- 看板列合同为每个临时清单维护完整列基线，逐项包含 `id/projectId/name/sortOrder` 及不安全排序标记；详情列与列端点必须双源一致，每次列创建或改名前后都须完整复读，只有同 ID 响应和复读均精确匹配才推进基线。删除临时清单前再次逐字段比较完整列集合；任何新增、缺失、改名、归属或排序竞争都拒绝删除并报告残留。列创建、列改名和项目视图写入均为结果未知时单发不重试。
- 合同取得排他门后、任何首个远端 create 前，必须先持久化授权绑定且含合法 runId／marker 的空 `pendingDidaContractCleanup`；保存失败则零远端调用，重启后继续阻断新合同。运行中把稳定 ID、候选清单、任务状态及完整列基线逐步扩充进 plan。恢复逐项 CAS，任务先于空清单；每次删除还必须先把 `sent-unknown` 持久化，再单发请求，崩溃或结果未知后永久只读复核、不重发。旧版无 plan 残留可由命令或冲突中心双确认领养唯一 A/B 组；已有空 placeholder 时只接受同授权、同 runId、同 marker 的组。多个组、普通任务、第三清单、列竞争或身份歧义均零删除拒绝；清理身份不进入 Notice 或普通诊断。
- 任务更新属于非幂等写入：生产 API 遇到网络中断或 5xx 时只发送一次并分类为“远端结果未知”。合同随后只按本轮精确清单 ID、任务 ID 与唯一标记复读，并核对标题、内容、优先级、时区、全天状态及时间语义；全部匹配才视为已生效并继续，未生效、身份不符或复读失败均停止且明确报告阶段，禁止重发同一更新。
- 滴答任务日期写入统一使用公开接口约定的秒级 `yyyy-MM-dd'T'HH:mm:ssZ`，UTC 偏移写为 `+0000`；合同生成值先对齐整秒，复读按时间点比较。合同测试根据复读结果识别账号的任务时间能力：独立起止值均保留为 `duration`，开始值为空或被折叠为截止值则为 `point`，其他转换视为合同失败。
- 提醒与重复规则的解释集中在 `src/domain/task-reminders.ts`。提醒只把精确的 `TRIGGER:PT0S` 解释为任务时间、把无歧义的负 ISO-8601 时长解释为提前量；周时长不能混用其他分量，`T` 后必须有时间项。重复规则拒绝重复键、额外等号、非十进制正整数、非法 UNTIL 以及 COUNT/UNTIL 混用；ERULE、未知键及非法值保持只读并逐字保留。只有基础任务 CRUD 与对应子能力都通过当前授权的合同后，任务编辑器才显示该字段的常用预设。队列必须持久显式 `writeFields`：只有用户实际更改、或冲突中心逐字段选择 Local／自定义的字段才能进入写载荷；远端值与本地值不同本身绝不能推断写入意图。连续更新合并时取字段意图并集，提醒、重复、日期和时区逻辑由所有视图复用，不另建第二套实现。
- 普通任务标签是无序集合，进入 Base／Local／Remote 前统一去重排序，禁止把滴答返回顺序当成竞争。跨清单精确任务查询允许把空响应或空数组解释为“不在该清单”，其他畸形响应仍拒绝。删除请求发送后的详情端点可能短暂返回旧对象，删除验证必须改查目标清单开放任务与完整已完成集合；任何复读失败或仍可见都进入 `reconciliation`，禁止重发。删除队列的 Local 必须是可持久化的 null tombstone；旧版误记为普通失败的删除在重启时自动隔离，只有权威集合证明不存在后才能采纳并移除本地快照。
- 已验证的 `point`／`duration`、任务 CRUD、真实父子任务、提醒、重复、`itemsRoundTripVerified`、`itemIdStableVerified`、看板归栏、任务重开和独立 `columnCreateVerified` 作为授权上下文的能力缓存写入 `data.json`。真实父子任务能力必须用唯一临时父／子任务依次证明创建挂接、最小 `parentId=""` 解除和重新挂接，且每步除 `parentId` 外其他字段不变；未经该独立能力证明，普通适配器不得发送 `parentId`。缓存不保存口令，只保存以独立域字符串和 SHA-256 生成的不可逆授权绑定；绑定不匹配、缺失或探针版本过期时全部能力失效。保存或清除 SecretStorage 口令必须通过服务的排他切换流程：先成功删除能力缓存，再改 SecretStorage；创建、更新、失败队列重试、同步、连接探测、任务身份复读、未知结果核对和冲突采纳等会读取或持久化远端事实的完整调用均持有共享授权租约，期间拒绝切换。`point` 模式只为原本就是单点的任务显示一个“任务时间”；若远端已有独立时间段，则以只读方式展示开始、截止、时区和全天状态，提交时直接复用远端原始值（包括秒和毫秒），允许修改其他字段但不得静默折叠。账号订阅或服务端能力变化后需要用户重新运行合同测试。
- Helix 项目向滴答的单向同步不得建立第二套写入引擎。所有阶段父任务和计划行动子任务的创建、更新、完成、重开与删除必须进入现有 `HelixService`、持久 `OfflineQueue`、共享 `RemoteWriteGate` 和唯一 `queueDrain` 单消费者；并发普通任务与项目任务也不得出现第二个消费者。创建先持久化命名空间化 `clientIdentity` 与稳定操作 ID，再允许发请求；`running` 中断恢复为结果未知，只核对不重发。`data.json.didaProjectionState` 是启用状态与精确目标的唯一配置源；父任务检查点、行动账本与操作收据均为非权威恢复状态，禁止保存完整任务。目标固定为唯一精确名称 `Helix Projects` 清单，任务不指定分栏、不创建看板或分栏，实际身份始终使用远端清单 ID、任务 ID 与父子关系；禁止模糊匹配。内部恢复身份不得写入远端 `content`／备注，历史可见标记在下一次受控更新时清空。启用跟随普通“自动同步”总开关，关闭时项目扫描与写入 readiness 同时归零。Project／Stage Markdown 和专用 Canvas 变化只负责防抖唤醒同一服务。协调器按 Helix 项目指纹单飞、按 Stage 逐个同步，重启从权威源重扫；只有写后指纹与输入一致才收敛，冻结／阻塞不记为完成。不得持久化第二份任务或另建远端写入口。
- 自动目标引导只在当前授权的清单 CRUD、真实父子任务和项目同步能力均已验证，且队列、冲突、恢复身份为空时运行。缺失 `Helix Projects` 清单时只允许一次“创建→精确复读→收口”；存在多个精确同名清单或已有不兼容恢复身份时停止，禁止猜测。Helix 不修改清单的列表／看板偏好，也不读取、创建或选择专用分栏。
- 任务多视图只消费当前同步快照，不保存任务、日期分组、时间块、年度汇总或象限的影子真值。列表、日、3 日、周、月、年与四象限共用 `src/domain/task-views.ts`：周一为周首；进行中任务按起止区间覆盖所有相交日期；已完成任务按完成时间单日归档；定时任务按任务自身 `timeZone` 投影日期与显示钟点，缺失或非法时区才回退到设备时区；全天任务优先保留远端日期字面值，防止时区换算漂移；无日期与非法日期不进入日历和年度汇总，但仍保留在列表和四象限。
- 滴答看板与列表消费同一组任务快照，只有选中单一滴答清单时显示看板入口。列表／看板标签只切换 Helix 会话呈现；远端 `project.viewMode` 必须由独立的“设为滴答默认”动作显式提交，离线进入现有项目队列并显示待同步，权限拒绝、缓存过期、冲突或失败不得伪装为已同步。能力矩阵固定为：`project.viewMode` 公开接口可读写；TickTick 官方 CLI `0.1.10` 已提供 V1 看板列列出、创建、改名端点，但未提供列删除，任务写模型也未声明 `columnId`；`task.sortOrder` 可读写但列内排序语义尚未验证。当前允许读取列、按真实 `columnId` 投影、未知归属进入“未分栏”、通过既有项目队列同步 `viewMode`。专用临时对象已证明列创建/改名和完整任务载荷中的 `columnId` 对当前账号生效；生产归栏进一步固定为仅发送 `id/projectId/columnId` 的最小白名单，并必须由独立临时合同证明其余字段未变化后才能开放。列删除/重排和列内拖动继续禁用，不能猜测未公开端点，不得接入需要账号密码的 V2 会话接口，也不得保存 Helix 自建列真值。
- 看板列和 `taskColumnIds` 保存在 `data.json.boardSnapshots`，它们只是可由下一次完整 `ProjectData` 重建的只读远端缓存，不进入项目或任务 Base/Local/Remote 写对象。每项携带 `projectId`、最后成功 `capturedAt` 和 `stale`；某一清单详情失败或缺少显式 `columns` 时原子保留该清单上次列及任务归属、标记过期并禁止看板写入，不影响其他清单。重复列 ID、清单身份不符、空名、非法 `columnId` 或非法结构只降级对应清单。详情项目只验证身份并提供列/任务，名称、颜色、权限、默认视图和排序继续以全局项目列表为事实。
- 生产卡片归栏必须与普通同步、队列消费、口令切换和合同测试互斥。写前精确复读完整列集合、详情任务和单任务身份，并确认详情端点、精确任务端点与本地快照的原分栏三方一致、本地没有该任务的待处理队列或未解决冲突；任一来源不一致都零写入停止。远端写入前先用 Canvas 无关的本地 CAS 把该清单看板持久化为 `stale`，再单发最小白名单。网络或 5xx 只允许精确复读，不得重发；远端拒绝、结果未知、写后复读失败或本地最终保存失败均保留冻结状态，等待下一次完整同步核对。生产与合同共用同一字段不变量：写后除 `columnId/etag/modifiedTime` 外的任务对象必须完全一致；若其他字段变化，保持看板冻结并创建 Base=Local=写前、Remote=写后的任务冲突，要求用户逐字段处理，后续同步不得静默吸收。冲突三方必须先经过与普通 `DidaTaskAdapter` 完全相同的同步投影并剥离 `columnId`，否则不得交给冲突引擎；字段选择和写后核对完成后由完整同步重建看板归属并解除冻结。成功提交只改目标任务的 `taskColumnIds` 并清除 `stale`，不得刷新整个看板的 `capturedAt` 或把单任务结果冒充完整新快照。
- 看板归栏只允许最小 `id/projectId/columnId` 载荷，生产入口同时要求基础 CRUD 与当前授权的看板能力；旧缓存、授权不匹配或合同有残留时保持只读。写后业务字段比较统一排除滴答服务器管理的 `etag`、`modifiedTime` 与 `etimestamp`，这些字段仍不得进入写载荷；未知字段和真正的业务字段变化继续视为失败。卡片只在联网、可写、看板新鲜、有其他目标列且能力已验证时允许拖动；只有落到不同真实分栏才提交，经过、取消、落回原列或落到“未分栏”均零写入。键盘与读屏使用可聚焦卡片上的 `Alt+←/→` 移到相邻真实分栏，复用相同提交入口；重复提交当前列由服务作为零远端访问的幂等空操作。失败不做乐观移动，成功复读并保存后才重绘；重名分栏按可见列序号标注以免误投。列删除、列重排和列内排序仍无合同证据，继续保持只读。
- 任务主标题的行内编辑复用普通任务更新队列与三方冲突逻辑，不另建写入通道。单击或键盘进入编辑，Enter/失焦提交，Escape 取消；空标题拒绝，失败恢复原显示。标题、完整编辑弹窗与快速创建共享同一任务真值，不保存界面副本。
- 本地项目任务直接读取 Stage `# 计划行动`：顶层清单项是任务，缩进清单项是其子任务。首次发现合法原生清单项时只补稳定 UUID、父 UUID、状态及可选本地属性标记；空占位、非清单正文和小节外内容不改写。标记在 Live Preview 隐藏，Markdown 清单仍可原生编辑和勾选；未绑定远端身份的勾选／取消勾选分别收敛为 `completed`／`idea`。标题、备注、状态、日期、时区、全天、优先级、标签和直接子任务使用同一 Stage revision 做单次 CAS，竞争时拒绝覆盖。任务页只合并即时投影，不复制本地任务到 `data.json`；行动绑定远端 ID 后以该稳定 ID 与滴答快照合并，禁止同一任务双重呈现，本地编辑仍回到 Stage Markdown。
- 滴答真实 `sortOrder` 可能超过 JavaScript 安全整数。此时规范化只标记 `sortOrderUnsafe`，不使用可能失真的值排序，也不在普通任务编辑时回写；只读投影改用稳定 ID 兜底。只有后续合同获得无损表示并证明方向、间隔、碰撞与重排语义后才能开放排序写入。
- 时间块以任务自身时区的墙上时间绘制：全天与定时分层，缺少单侧时间、起止同一瞬间及完成记录统一投影为向后 15 分钟的单点块，跨日任务按每天切片；重叠块只在相交簇内分配泳道。夏令时跳跃和重叠按当地钟面位置稳定展示，不把显示时长反写为远端持续时间。
- 时间块已整合到日、3 日和月视图，不再保留并列的独立入口。日与 3 日调用同一个时间网格，月历调用同一个 `buildTaskTimeBlocks` 投影并显示定时任务的开始钟点；日期范围、任务区间、时区换算、单点规范化及重叠泳道只允许存在一份领域实现。UI 只能组合投影，不得复制算法、缓存派生任务集合或维护相互漂移的视图状态。
- 任务筛选是会话态。滴答清单作为一级导航只存在于侧栏；状态、标题/备注搜索和折叠式高级筛选位于同一工具层。高级筛选仅包含 Helix 项目、标签、精确优先级和日期，且可与当前滴答清单、状态及搜索叠加。搜索覆盖标题、内容、描述和检查项标题；日期筛选按任务区间与目标日期范围是否相交判定。同步快照不再包含选中清单、项目或标签时清除该会话条件，禁止界面显示“全部”但内部仍以消失值过滤。
- 本地与滴答任务详情共用 Dense task canvas 壳层、标题层级和响应式布局；滴答独有的清单、提醒、重复与关联只进入一个扩展区，不复制本地任务编辑真值或另建第二套详情页。任务备注不作为独立大区展示，未编辑时必须逐字保留远端值。
- 任务完成控件必须直接反映当前 `status`：已完成显示绿色勾选且控件语义为“重开”，未完成才显示“完成”。完成写入只保存状态意图，`completedTime` 由滴答生成；若排队期间远端也已完成且本地相对 Base 没有其他业务改动，应直接采纳远端完成时间并收口队列，不得制造冲突、重复完成或发送重开。
- 快捷属性由唯一的 `src/domain/task-quick-entry.ts` 解析与生成候选：`~清单`、`#标签` 和 `!高／!中／!低／!无` 只有在明确匹配时才从标题移除；含空格的清单名必须使用引号。未知清单、同名清单、多个不同清单、未知优先级或多个不同优先级均保留相应原文并阻止写入，不得静默择后。候选只替换光标所在 token，创建器和任务编辑器共用同一函数及上下键、Enter/Tab、Escape 语义；创建器提交前显示解析后的标题和属性，并允许撤销解析、按普通标题处理。任务标题、清单、标签和优先级仍以滴答为真值，Helix 项目/阶段关联继续独立保存。
- 创建滴答清单必须进入既有离线队列、写后复读和冲突处理通道。名称先去除首尾空白并拒绝当前快照中的精确同名，颜色仅接受 `#RRGGBB`；网络或 5xx 的结果未知不得盲目重发。`local-project-*` 只表示创建结果尚未取得远端身份：侧栏可显示并进入冲突中心核对，但任务创建器和任务编辑器必须排除它；服务入口必须在任何快照或队列写入前拒绝新任务或已有任务引用。若异常旧任务当前已引用该 ID，编辑器只读显示当前值并冻结任务保存。确认远端 ID 并完成同步刷新后才允许作为任务清单。当前不建立跨对象离线依赖，因此不存在把任务队列静默迁移到新清单 ID 的路径。侧栏只把清单作为任务导航，不复制清单或任务为 Helix 项目事实。
- 项目联动使用稳定远端身份：一个 Helix 项目在项目 Markdown 中至多显式绑定一个已复读的滴答清单 ID，同一清单不能被两个 Helix 项目占用；映射新增、切换和解除均使用打开时 revision 与旧映射基线比较，待核对的 `local-project-*` 禁止绑定。项目页提供独立确认动作，保存前重新读取精确远端清单 ID，不按标题、目录位置或 Canvas 坐标猜测。
- 本地阶段行动以 marker UUID 作为 Helix 内稳定身份，子任务同时保存父 UUID；项目滴答投影开启后，项目 Markdown 才保存父 Task 稳定 ID、行动 marker 才追加 owned item 稳定 ID，远端身份始终是 `parentTaskId + itemId`。禁止按标题或数组位置领养。Task Reference 仅服务普通滴答任务引用，不承担项目行动真值。
- 四象限每项任务都以同一当前时刻在自身时区的“今天”判断紧急性，不受设备日期线差异及日历导航锚点影响，完成任务不进入象限。重要优先级阈值和紧急天数属于 `HelixSettings` 中的本地显示规则，只能通过串行设置通道持久化；必须先保存成功再发布运行时，规则变化不得改写滴答任务真值。

## 5. Markdown 与 Canvas 安全

- 写入前记录文件哈希；提交时哈希变化则停止并提示冲突。
- Markdown 只维护 `helix-*` 属性和标记清晰的自动摘要块，保留正文、未知属性、BOM 与换行风格。
- 模板是“新文件的用户正文”来源，不是项目、阶段或复盘的影子真值。Helix 固定写入身份 frontmatter、一级标题及复盘自动摘要边界；模板不得覆盖这些托管区。默认模板根目录为 Vault 相对路径 `Template`，实际文件为 `Template/Helix/{Project,Stage,Daily Review,Weekly Review,Monthly Review,Yearly Review}.md`。仅支持 `{{title}}`、`{{date}}`、`{{periodStart}}`、`{{periodEnd}}`、`{{project}}`、`{{stage}}` 六个占位符，未知 Markdown 与未知占位符原样保留。
- 首次安装在用户确认模板目录后才创建默认模板；取消零写入，之后可在设置中完成。已有安装缺少模板字段时按既有授权迁移到 `Template` 并只补齐缺失文件。目录必须是 Vault 内相对路径，拒绝空值、绝对路径、NUL、反斜杠／UNC、盘符以及 `.`、`..`、`~` 路段；目录/文件冲突解释性失败。路径判定由无 Obsidian 依赖的共享模块统一执行，恶意 `data.json` 路径进入恢复模式。
- 模板补齐、单份渲染、批量渲染和目录切换共用同一串行锁。一次项目或多阶段创建必须批量读取同一目录快照；目录切换按“补齐缺失文件→持久化设置→发布运行时”顺序执行。任一步失败仅回收该次新建且内容未变的模板；回滚竞争必须报告残留路径，且不得切换运行时目录。并发流程已先创建的文件视为既有内容，绝不覆盖。
- 项目 Markdown 是项目身份、名称、状态和正文的唯一事实；阶段 Markdown 是阶段身份、所属项目、状态和正文的唯一事实。活动阶段由各阶段的 `helix-status` 派生，允许同项目内多个 `active`。
- 任务关联使用独立的 `helix-kind: helix-task-reference` Markdown，每份只保存关联 UUID、`provider=dida`、已确认的滴答远端任务 ID、一个 Helix 项目 ID、零到多个阶段 ID 以及创建/更新时间。任务标题、状态、内容、时间、优先级和滴答清单不得复制进关联文件或 `data.json`；项目/阶段 Wikilink 只是可重建的 Obsidian 反向链接投影。
- 任务字段与 Helix 关联属于两个权威域，任务弹窗提供独立保存动作。只改关联不得创建滴答同步队列；只改滴答字段不得重写关联 Markdown，也不得把其中一个动作的成功显示成两侧整体成功。
- 只有已取得远端 ID 且保存前实时复读确认的任务可以建立关联；`local-*` 临时任务禁止成为关联真值。普通任务关联不依赖项目滴答投影或清单映射，任务移动清单、完成或暂时不在同步覆盖范围内时均保留关联；远端删除不级联删除关联。任务被人工重建成新 ID 时，只允许用户明确核验后重绑，禁止按标题或时间猜测，并再次核对远端返回身份一致。
- 关联保存必须用弹窗打开时的关联 UUID 与 Markdown revision 做比较；文件在提交前变化、同一任务出现多份关联、关联 UUID 重复或结构损坏时停止写入。项目/阶段删除或阶段改属其他项目时保留原 ID 并显示断链，用户可以明确重新绑定或解除，不静默清理。
- 项目与阶段状态编辑只允许在对应 Markdown revision 未变化时更新 `helix-status` 与 `helix-updated`；阶段进入 `completed/terminated` 才写 `helix-closed`。旧项目 `archived`、旧阶段 `planned/closed` 仅兼容读取为 `terminated/idea/completed`，绝不批量回写；未知值明确诊断。不得重写用户正文、未知 frontmatter 或用 Canvas 摘要反向覆盖 Markdown。
- 新阶段文件使用 `Stage-XX.md`；一级标题为 `阶段 X · 自拟标题`，并写入 `helix-stage-code` 字符串和整数 `helix-sequence`。`sequence` 只作稳定文件路径和单调高水位，绝不因删除而复用；用户可见 `stage-code` 则按当前继承／分支／合并图维护，删除后在同一原子事务中紧凑重算受影响编号、标题与聚焦引用。缺少 code 回退 sequence，存在但非法则拒绝操作。
- Canvas 的 `helixStageCodes` 仅是当前展示编号索引，可由 Markdown 与关系图重建，绝不反推或承载阶段关系、状态、身份或正文真值。当前活动的项目／阶段笔记以公开状态栏入口显示中文状态；未知手工值仅诊断、零写入，编辑仍复用同一 Markdown CAS 与状态候选控件。
- 项目页纯读取只报告 `canvasRepairRequired` 与中文原因，绝不为缺失节点、摘要、编号账本或关系正规化写入 Canvas。只有用户明确点击“修复 Canvas”时，才在恢复模式写入闸门后使用连续稳定快照、受管 Markdown 最终修订复核与 Canvas CAS 应用同一修复计划；任一竞争均保持 Canvas 零写入。
- 专用 Canvas 是项目/阶段节点布局和阶段关系的唯一事实；`data.json` 不保存项目、阶段、关系或布局副本。
- 托管项目节点必须包含 `helixManaged=true`、`helixNodeKind=project`、`helixProjectId`；新托管阶段节点使用 `helixNodeKind=stage`、`helixStageId` 和所属 `helixProjectId`。旧 `helix-kind: helix-cycle`、`helixNodeKind=cycle`、`helixCycleId` 与 `Cycle-XX.md` 仅兼容读取，不静默改名。身份必须与对应 Markdown 唯一匹配。
- 托管物理边只允许阶段指向阶段，并且是唯一结构事实。用户可见名称为“推进／分支／合并”；内部稳定枚举仍为 `inherit/branch/merge`，旧 Canvas 的“继承”标签继续兼容读取。`helixRelation` 按全图正规化：目标入度不少于 2 时全部入边为合并；否则来源出度不少于 2 时全部非合并出边为分支；其余为推进。合并组必须覆盖同一目标全部入边，拒绝自环、重复边、悬空节点和有向环。
- 无标签边、非托管边、未知节点、未知 JSON 字段和用户布局原样保留，不自动解释。普通原生边只有在两个端点均为已识别阶段时才显示为候选；用户必须逐条确认，跨项目还需独立勾选。提交重新核对候选 `edgeId`、物理端点和 Canvas revision，并执行自环、重复和 DAG 校验；通过后只为该边增加托管及派生关系字段，保留未知字段。
- 跨项目阶段关系允许，但创建前必须显示来源项目并明确确认。
- 旧 `helix-parents`、`helix-active-cycle`、`helix-predecessor` 和 `derives-from` 边不得自动转换。Helix 必须逐项展示来源和处理方式；取消时零写入。用户可确认保留旧数据而不推断关系。
- 新建阶段的 Markdown 与 Canvas 节点/边按一个计划写入。Canvas 比较写入失败时，将本轮新建且未被用户改动的文件移入仓库 `.trash`；回滚遇到竞争则停止后续写入并报告。
- 阶段卡片右侧加号是创建关系的语义入口，不再重复询问关系类型和前置阶段。单卡加号在来源没有后继时创建继承；再次从已有后继的来源点击加号时创建或扩展分支，并把原有单一继承边转换为分支。用户点击具体来源卡片的加号即为对该派生动作的明确确认。
- 关系图中多选两个及以上阶段后，点击其中任一卡片的加号会以全部所选阶段为前置创建合并节点，来源顺序取当前拖动后的画布位置。若某个来源已有继承后继，该继承边会在摘要中预告并随本次提交改为分支，从而保持 DAG 关系合法。跨项目所选仍要求单独确认，并明确显示新阶段归属的被点击卡片所属项目及外部来源；已有关系的其他修改继续通过关系管理入口完成。
- 自动创建必须携带弹窗展示时的完整预期意图，包括关系类型和需要转换的继承边 ID。服务提交时从 Canvas 快照重新推断并逐项比较；用于推断的 Canvas 哈希还必须与后续写入的 revision 一致。任一变化都在创建 Markdown 前拒绝，禁止按过期语义静默提交。
- 结构变化默认只整理受影响的弱连通分量；同项目内不在该分量的阶段和项目兼容锚点必须保持原坐标。关系图工具栏不提供全图整理：未选择时禁用；选择项目时只整理该项目；只选择同项目阶段时按所选连通块分别以前一个直接父节点为锚点整理，已有兄弟保持不动，新位置按稳定行距避让；跨项目选择时禁用。仅 Helix 托管阶段参与，层级按物理 DAG 计算，跨项目合并仍留在目标项目容器，非托管节点永不移动。整理只改变会话布局，用户点击“保存当前布局”后才以一次 Canvas CAS 覆盖唯一当前布局。折叠只影响投影，不改变物理节点、边和坐标。
- Canvas 内维护每个项目的阶段序号高水位；删除或恢复旧阶段不会回退高水位，新阶段不得复用已删除的 `Stage-XX.md` 路径。
- 删除阶段必须明确确认。删除 V 时可选择以 `predecessors(V) × successors(V)` 桥接路径；已存在边复用，禁止重复边。计划必须分别冻结桥接与不桥接两套受影响节点，以及每条旧边的 `edgeId`、原类型和新类型；弹窗随开关显示当前模式的新增、复用、跨项目、精确重标清单和布局节点数。新增候选超过 24 条时禁止一键全桥接并使用不桥接口径。跨项目桥接另行确认。完整计划先做 DAG 校验，并与布局、正规化结果一起进入同一 Canvas after 镜像。
- 删除提交先用 Canvas 版本比较写入完整 after 镜像，再仅在 Markdown 原路径存在且哈希未变时移入仓库 `.trash`；Markdown 被并发改名或删除时视为冲突，并用刚写入的 Canvas 版本执行回滚，回滚再竞争则冻结并要求人工检查。项目唯一阶段不得删除。
- 已有关系允许在内嵌画布中选择、调整来源和删除。继承、分支、合并不是独立可编辑真值，始终由完整物理边集的入度与出度重算。关系更改只触碰明确的 Helix 托管边；每次提交前重新验证来源、跨项目确认和 DAG，竞争时拒绝覆盖。
- 项目页是内嵌的 Canvas 式前端：关系图、卡片和看板均从 Markdown/Canvas 即时读取。关系图不把项目渲染成与阶段同级的普通节点；它按该项目当前可见阶段的 Canvas 坐标计算一个底层自适应容器，使用项目色的单一透明填充而非渐变，容器标题打开项目 Markdown，并承载项目状态与完成折叠入口。项目托管节点仍作为原生 Canvas 的兼容身份锚点保留，不因前端容器投影而删除、改型或成为第二份项目真值。阶段卡片只是摘要和入口，点击后打开对应 Markdown。
- 项目颜色只接受规范 `#RRGGBB` 或空值，通过项目 Markdown 的哈希比较写入；颜色只作项目区分，完成状态必须同时使用绿色勾选和文字，不得仅依赖颜色。
- 项目选择是会话态：关系图保留全局 DAG 并弱化未选项目，卡片和看板按选择真实过滤，必须提供“全部项目”。项目胶囊内包含独立调色入口；点击项目标签必须以该项目容器外框为目标，同时计算可放大或缩小的适应比例，并在同一相机动画中插值逻辑中心与缩放；点击“全部项目”以所有容器的内容边界恢复全局适应。结构操作保持当前缩放并聚焦具体阶段。选择和相机状态不写入 Canvas。
- 空白左键拖动用于矩形框选当前投影中的可见阶段，卡片显示盒与选择矩形相交即命中；普通框选替换选择，Shift 框选追加选择，单击空白清空。空格加左键和鼠标中键的平移优先级高于框选；卡片拖动、关系把手和所有按钮不启动框选。Escape、`pointercancel` 或失去指针捕获必须恢复框选开始前的选择；折叠隐藏节点与项目兼容锚点不得进入结构选择。框选是会话态，命中计算保持对可见节点的一次线性扫描。
- 完成折叠只持久化版本化的项目 ID 集合。每个项目内 `closed` 阶段诱导子图的最大弱连通分量（至少两个节点）分别折叠成纯投影头；不允许跨越 active/planned 阶段把互不连续的完成节点强行合成，否则会伪造物理 DAG 不存在的视觉环。隐藏节点、边和坐标不删除，外部关系以不可编辑聚合边显示，点击聚合边或头节点摘要先展开。该投影不得进入创建、拖动、批量选择或关系编辑的结构输入。
- 内嵌画布“无限”定义为实践上无边界：Canvas 原始坐标是唯一事实；屏幕 origin 和四向动态扩边仅存在于内存，并在左/上扩边时补偿滚动位置，不批量改写节点坐标。每次四向扩边必须按当前缩放换算出稳定的屏幕余量，低缩放时不得因不足 1px 的补偿形成连续扩边循环。坐标必须有限且位于安全范围，适应全部按项目容器的逻辑边界计算。按钮、触控板和快捷缩放都保持缩放前的逻辑视口中心；结构操作后的聚焦动画是会话态，不写入 Canvas。项目标签和双击阶段卡片都按目标外框计算比例并居中聚焦，最大缩放统一为 120%；卡片内打开、创建、连接和删除按钮保持原语义，不触发双击相机导航。相机过渡默认 420ms，缩放与逻辑中心使用同一缓动进度；`prefers-reduced-motion: reduce` 下必须无动画跳转。
- 多卡移动必须在一次 Canvas 比较写入中提交。检测到竞争时回滚屏幕上的临时位置并提示用户，禁止并发逐卡写入或吞掉错误。
- 阶段删除不是跨文件原子事务，因此在 Canvas CAS 之前必须先创建内部日志 `Helix/.transactions/stage-delete.json`。隐藏目录和未注册扩展名不会稳定进入 Obsidian 的 `TFile` 索引，仓库层必须在索引缺失时回退到 Vault adapter 读取并校验原始内容；清理时优先使用仓库废纸篓，未索引的机器日志则在再次核对内容哈希后直接移除。日志保存阶段身份、原路径和哈希，以及 Canvas 写入前/后的完整内容与哈希；任一时刻只允许一个阶段删除事务。成功删除或完整回滚后必须清理日志。
- 插件启动时先恢复未完成的阶段删除：Canvas 仍为旧版本且 Markdown 保留时撤销未开始的事务；Canvas 已为新版本且 Markdown 未变时继续移入废纸篓；Markdown 已删除时确认完成；Markdown 被修改或改名时仅以新 Canvas 哈希为前提回滚；Canvas 同时出现未知版本时冻结项目工作区并要求人工检查。日志内容、路径或哈希损坏时同样冻结，禁止猜测或静默覆盖。
- 关系图工具栏的撤销／重做只管理尚未保存的会话布局，最多 50 步且不写 `data.json`；保存当前布局会覆盖唯一 Canvas 布局并清空旧布局撤销栈。结构变更仍以精确 Canvas／Markdown 前后镜像保证事务恢复；跨文件操作先写唯一临时日志 `Helix/.transactions/workspace-history.json`，v2 日志按 `prepared → markdown-applied → canvas-applied` 推进，并在每次文件写入前复核日志。Canvas 起终点相同时按 phase 与全部 Markdown 起终态恢复；任一文件未知、相位混合、身份漂移、路径重复、日志竞争或多日志并存均冻结，不猜测或静默覆盖。v1 日志保持只读兼容恢复。
- Stage 聚焦引用只由 Canvas 托管入边派生：新建、连线、纳管、换边、断边及会改变存活目标入链的阶段删除，都把受管引用、Canvas 和 Markdown 新增／删除放进同一 v2 日志。无派生变化的叶子删除继续使用既有 `stage-delete` 合同；普通引用文字永不反推关系。
- 运行中聚焦同步以 `Helix/.transactions/stage-focus-bridge.json` 保存非权威 Base 检查点和逐 pair 冲突；同一来源的多个反向候选必须先归并并逐目标复核，候选不一致或任一兄弟目标已有正文／结构编辑时只冻结相关 pair，禁止按监听顺序覆盖。自动同步不进入用户撤销栈。冲突内容三选一仅适用于受管结构完整的双边正文竞争；结构冲突只能显式重建受管块或打开 Markdown 手工修复。
- 聚焦冲突解决先以状态 revision CAS 认领 `pendingResolution`，再执行可恢复 Markdown 事务并收口检查点；认领竞争时正文零变化，全部文件处于 after 时可在启动或监听前完成恢复。文件呈混合或未知版本时保留待决记录、冻结整个项目工作区并把恢复问题持久显示到冲突中心，禁止后续关系写入继续改变现场。
- 所有项目结构写入、撤销、重做与可能修复 Canvas 的读取入口共用串行命令通道。普通 Markdown/Canvas 比较写入使用 `Vault.process` 在原子回调内核对内容哈希；用户文件和未索引机器日志删除都先原子改名为确定性的 `.helix-delete-claim`，在认领路径再次复核内容哈希，不变才移入仓库废纸篓或移除；竞争及删除失败恢复原路径并报告冲突。插件启动必须先递归恢复认领文件，再恢复撤销或阶段删除事务；若原路径已被占用则保留认领文件并冻结，禁止覆盖。拖动操作还必须绑定界面开始拖动时看到的 Canvas revision。任何无法与历史顶端镜像对应的外部 Canvas 修改都会清空会话历史，撤销本身则在 revision 或 Markdown 身份变化时解释性拒绝。
- 项目页启用写操作前必须连续读取两个语义一致且 Canvas revision 相同的快照；同步产生的短暂无效 JSON、身份不完整或前后变化只允许有限重试。稳定快照与修复提交之间 Canvas 再变化时零写入拒绝；缺失 Canvas 必须排他创建，目标在创建前出现即冲突，不得再次读取后接管；连续失败时显示最后一次有效快照的只读 Markdown 入口，不得用旧快照写回。项目和阶段 Markdown 以稳定 ID 全库发现，成功快照维护路径索引，使文件移出默认项目目录后仍可监听修改、删除和重命名；未知外部 Markdown 的新建与修改需去抖检查项目身份，覆盖空文件建立后再填充 frontmatter 的同步写法。
- 删除阶段前必须检查所有相连边；若存在原生 Canvas 非托管边，默认拒绝删除并要求用户先移除或显式纳管，禁止按端点静默删除用户关系。
- 删除项目必须逐字输入“我确认删除该项目。”；提交前复核 Project、全部 Stage 身份与 Canvas revision。未启用项目投影或没有远端绑定时，若项目容器或阶段连接任何非托管／旧版边则零删除拒绝；通过后在同一可恢复事务中移除项目及阶段节点、托管关系、编号索引和聚焦派生，并把 Project 与全部 Stage Markdown 移入 Obsidian 废纸篓。若项目已有投影绑定，必须先经现有 OfflineQueue 按账本中的精确任务 ID、父 ID 与 `Helix Projects` 清单 ID 逐个删除行动，再删除父任务；每次发送前持久 tombstone，结果未知时禁止重发，本地删除失败时保留已验证父 tombstone 以阻止后台复活，只有本地事务成功后才释放。不得按标题或远端备注删除，不得触碰非 Helix 拥有的滴答对象。
- `data.json` 集合、事件类型载荷与确定性 ID、快照哈希与实体 ID、队列对象/操作类型、由三方快照重算的冲突字段、审计及进行中标记在载入时做结构校验；集合 ID、事件语义和正在进行任务不得重复，阻塞队列必须引用同一对象的真实冲突。损坏条目不会参与同步，插件进入禁止写入的恢复模式，并在冲突中心显示问题及脱敏诊断。

## 6. 分析与挑战

- 事件必须具备基于 SHA-256 的确定性 `eventId` 并按语义去重。Helix 发起且经远端验证成功的任务完成操作必须立即入账，不依赖 31 天补拉窗口。
- 重复任务按 occurrence 计奖；任务重开、习惯撤销与专注记录删除会回收对应统计、奖励和挑战进度。
- XP、等级、徽章、热力图和趋势图全部由事件重算；挑战达标事件冻结当期指标、目标、周期边界、奖励和规则版本，后续 Release 修改挑战池不会篡改历史奖励。任务重开或专注删除使冻结口径下的进度跌破目标时不再计入奖励。
- 滴答专注 `duration` 按毫秒转换分钟，若可靠的 `startTime/endTime` 存在则用于单位异常交叉校验并兜底。当前同步覆盖到同一专注记录时，仅允许以相同确定性 ID 替换本地派生的 `focus-completed` 分钟值；任务、复盘、挑战等不可变事件绝不通过此路径覆盖。历史挑战领奖事件只有当前进度仍达标才展示为已领取并计入奖励，修正后的低进度不会删除历史记录或触碰远端。
- 默认使用正向鼓励；压力和严格模式为显式可选。
- 周/月挑战由本地确定性轮换生成，新主题随插件 Release 更新，不依赖后端推送。
- 任务完成、复盘关闭等本地事件统一经过“追加事件→重新评估挑战→刷新运行时”入口，达标奖励无需等待下一次滴答全量同步。

## 7. 已知外部限制

- 滴答公开更新接口尚未证实支持 `If-Match` 原子条件写入。未通过真实合同测试前，只承诺 Helix 自身不静默合并，并采用写前/写后验证缩小竞态窗口。
- Obsidian Sync 不向插件公开任意 Markdown 的服务器三方版本。Helix 可以保护自身结构化写入并冻结冲突，但不能替代 Obsidian 对普通用户正文的文件级冲突处理。
- 当前私测版只承诺单一设备编辑 Task Reference；其他设备可继续通过滴答编辑任务。运行中 revision 比较能拒绝竞争覆盖，但插件关闭期间的同步器最后写入无法构造 Base/Local/Remote 三方版本。发布前若要承诺多设备编辑 Helix 关联，必须升级为不可变修订/双头检测并在 Helix 内逐字段合并。

## 8. 上游参考

- 隔离写入合同取得排他租约后、任何能力失效或远端调用前，必须确认项目投影已停用，生产队列、未解决冲突、分栏恢复与收据清理均为空；禁止合同临时队列消费者处理真实生产操作。
- 项目投影激活与合同测试、授权切换及其他排他远端事务互斥；激活写配置前再次确认生产队列、冲突和恢复状态为空，避免合同运行中途启用后在能力发布时意外唤醒。
- 滴答同步及任务日历的范围、周首、完成日期归档行为参考 `CYZice/Obsidian-DidaSync@c33aedd`；Helix 未照搬其前端，并补充跨日与全天时区语义。
- 任务跨清单移动沿用 DidaSync 核对到的数组载荷合同：仅一次 `POST /task/move`，正文为单元素数组；不根据响应正文重发。移动后的权威证明是源、目标清单身份与 `data.tasks` 的有界只读复读：只有目标命中且来源不存在才能采纳移动结果；确认仍在来源可作为未移动事实，双重可见或双重缺失一律保持结果未知冻结。数组、项目身份或字段歧义立即停止自动处理。
- 所有滴答接口共享一个持久化请求治理器，跨项目、任务、习惯与专注按不快于每秒一次串行发送，禁止突发；下次允许发送时间随授权绑定持久化，重启不能绕过间隔，异常远期值直接进入恢复而不长时间等待。`429` 支持秒数或 HTTP-date 的 `Retry-After`，保留真实可表示期限并对无效／溢出值采用安全期限；HTTP 500 的结构化 `exceed_query_limit` 使用 15／30／60 分钟逐级冷却。冷却状态绑定当前授权的不可逆哈希，只保存饱和安全整数接口计数与限流时间，不保存路径、对象 ID、正文或凭证；结构无效即进入恢复只读。若已观察到限流但普通 `data.json` 保存失败，当前实例先永久闭锁，并向独立 SecretStorage 端口写入只含版本、授权绑定、固定原因和时间的紧急闭锁；重启必须先读闭锁且零发送，写请求对外仍保持远端结果未知。授权切换只有在新绑定的空请求状态成功持久化后才能清除旧闭锁。任一恢复问题下所有远端入口零发送，必须先修复本地问题，禁止伪造清理旁路。普通后台读取在冷却期零发送且不消费探针；本地状态健康时，合同残留的显式只读恢复可使用每个冷却窗口至多一次的探针。窗口内探针或自然到期后的首次成功只读都会清除查询限流级别；其间的写入或瞬时读取失败必须继续保留待恢复标志。限流立即返回上层，不在 `RemoteWriteGate` 内等待或自动重试；非幂等写仍只发送一次。
- 写入合同开始前必须在取得 `RemoteWriteGate` 之前检查全局冷却；v13 主体最多消费 250 次调用，`finally` 安全清理使用独立保留的 40 次预算。合同编排器、测试 Vault 临时 Project／Stage 主链路及其生产队列探针（含删除写前复读）必须共用合同 API 和已持有的排他租约，禁止从排他事务内部再次申请共享租约或绕过预算；合同主体、随附清理、残留领养和恢复清理统一使用 30 秒单请求超时与单次尝试。Vault 投影同步会在远端步骤间回填 Markdown，完整 synchronize 必须处于项目自写 quiet-window 内。投影更新使用稀疏任务时，Local 三方快照必须先从远端 Base 补齐未写字段，只允许 `writeFields` 表达显式清空；失败路径须在所有远端 ID 已登记进合同清理票据后，移除临时项目产生的队列、冲突、收据、事件和 Markdown／Canvas，身份不全则保持冻结。v9 基础合同真实成功路径为 122 次，v10 为 168 次，v11 为 185 次，v12 为 194 次，均未触发限流。v13 前六次真实尝试依次暴露两处排他锁自锁、自写监听竞态、状态收口误报、无日程默认时区误判和稀疏快照假冲突；修复后最终合同完整通过，任务 CRUD、父子任务、项目投影、看板归栏、分栏创建与重开能力已绑定当前授权持久化，临时远端及本地对象全部清理且未触发限流。已有 `pendingDidaContractCleanup` 的恢复不受主体预算限制，但仍服从全局串行和每窗口一次的显式只读探针；任何预算耗尽都安全中止并保留可恢复计划。
- 只有状态为“进行中”的 Stage 才可首次创建滴答父 Task，标题等于阶段名；该 Stage `# 计划行动` 的每个任务对应带稳定 `parentId` 和 `Helix Projects` 清单 ID 的普通子 Task，不写入父任务 `items`，父子任务的远端 `content` 均为空。已绑定 Stage 改为“已完成”时必须完成父任务；其他状态不得凭空创建父任务。Helix Project 只在本地组织 Stage，不创建同名远端项目父任务。只有当前授权的 v13 合同完整成功并持久化 `taskParentingVerified` 与 `projectProjectionVerified` 后才允许自动启用；看板归栏与分栏创建能力不再是该功能前置条件。创建、改名、完成、重开和删除全部复用普通任务队列、写前精确复读、写后按 Task ID 再读验证、结果未知冻结与逐字段冲突流程。Stage Markdown 保存父 Task ID，隐藏行动标记保存行动 UUID 与远端 Task ID；同步账本仅保存 Base 和冻结检查点。不得按标题领养，不得在结果未知时自动重发。历史 items 账本、队列与冲突仅用于向后兼容的只读诊断。
- 项目后台协调器必须先取得全局 readiness=true 才能扫描候选；readiness 未初始化或为 false 时零扫描、零同步，只有 false／unknown→true 才全局失效缓存并重新唤醒。成功批次只在确有远端变更时发送一次 Obsidian 通知，按唯一项目和变更数汇总；回填引发的再次扫描不得重复计数或提示。冻结／失败按项目与输入指纹去重并导向冲突中心。
- 项目投影激活在排他授权租约中复读目标清单时，必须复用该租约内的 catalog reader；禁止从排他租约内部再次申请共享租约。预览哈希仍按 fresh catalog 与 fresh Project／Stage 数量重新计算，调用方不得把旧预览直接写入配置；无分栏目标使用内部哨兵值，绝不能发送为远端 `columnId`。
- 项目行动的日程能力必须在进入持久队列和任何远端调用前验证；当前账号为 `point` 时，独立起止值是永久本地能力拒绝，不得形成可重试队列或永久冻结身份。用户修正 Markdown 后由后台自然重扫。结果未知的任务只能按既有操作收据中的精确任务 ID，再核对清单、父任务、标题、空 `content`、备注、日程、优先级、状态与标签集合；滴答标签大小写规范化不构成差异，时间按同一瞬间比较。取消可见 marker 后不得退化为按标题领养，无法取得远端 ID 时保持冻结。
- 项目页直接纳管或编辑行动后必须按 `projectId` 使协调器已收敛指纹失效，不能只普通唤醒；否则 Markdown 已保存但后台会误判为无变化。插件重载后即使投影配置仍启用，运行态未完成首次成功只读同步时 `connected=false`，readiness 必须保持 false 且零写入；显式禁用后本地编辑只积累权威差异，重新 fresh 预览确认并恢复 readiness 后才允许补齐。
- 已删除专用目标后的停用配置只能在投影账本、父任务检查点、父 Base、收据清理和分栏恢复全部为空时清除；该操作同时移除 target、激活版本和预览凭证。任一恢复身份存在都必须拒绝，不能为了界面干净而丢失安全清理所需的唯一远端 ID。
- 授权切换是两阶段闭锁事务：改 SecretStorage 前先写含旧／目标授权绑定与固定 `prepared` 阶段的 transition latch，旧请求控制状态原样保留；SecretStorage 写入或新绑定空控制状态保存失败时 latch 必须保留，后续请求零发送。只有真正不同的新绑定状态成功保存后才能清 latch、精确移除“限流状态保存失败”运行时问题并重置 governor，其他恢复问题保留；同绑定重设不得清冷却或闭锁，清除口令后再恢复原绑定也保守保留旧限流 latch。排队请求在间隔结束后必须再次复核授权绑定和 latch，旧授权请求不得穿透切换窗口。
