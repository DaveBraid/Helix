# 架构与边界

本文件定义 Helix 的长期架构、权威数据边界、核心数据流和必须显式处理的边界情况。实现发生结构变化时更新本文件；日常进度不写在这里。

## 1. 权威数据边界

| 数据 | 权威端 | Helix 行为 |
| --- | --- | --- |
| 任务、远端清单 | 滴答清单 | 缓存、编辑、离线排队、显式冲突合并 |
| 习惯定义与打卡 | 滴答清单 | 可在 Helix 新建、编辑和打卡，远端记录为最终事实 |
| 专注记录 | 滴答清单 | 导入各设备记录，Helix 计时完成后回写 |
| 项目身份、名称、状态、颜色与正文 | 项目 Markdown | Helix 发现、创建、打开和安全写入 |
| 阶段身份、所属项目、状态与正文 | 阶段 Markdown | 自动编号“阶段 X”，标题由用户自拟；支持多个 `active` 阶段 |
| 滴答任务与 Helix 项目/阶段的关联 | Task Reference Markdown | 每个已确认远端任务至多一份关联；项目 0..1、阶段 0..n |
| 日周月年复盘 | Helix Markdown | 模板生成、数据辅助、用户回答 |
| 阶段关系与布局 | 唯一主 Canvas | 只解释明确托管的继承、分支、合并边并强制 DAG |
| “正在进行” | Helix | 不写入滴答标签；首页显示前三项并可展开 |
| 统计、XP、成就、挑战 | Helix 事件账本派生 | 不以可变累计值作为唯一事实 |

## 2. 模块结构

- `src/integrations/dida`：HTTP、能力探测、正规化及任务/项目/习惯/专注适配器。
- `src/sync`：Base 快照、离线操作、三方差异、冲突解决、写前复查与写后验证。
- `src/domain`：项目、阶段、复盘、Canvas DAG、事件、分析、XP 与挑战。
- `src/storage`：SecretStorage、插件持久状态、Markdown/Canvas 安全读写。
- `src/ui`：Obsidian ItemView 和界面组件，只调用服务接口。

## 3. 同步状态机

每个远端对象维护：

- Base：上次已验证同步版本，含数据、`etag`、修改时间和正规化 SHA-256 哈希。
- Local：Helix 当前本地版本。
- Remote：本轮同步新拉取版本。

规则：

1. 仅一端相对 Base 变化时可以自动同步。
2. 两端都变化且结果不同，暂停整个对象并建立冲突；即使变化发生在不同字段，也必须由用户确认后提交。
3. 用户逐字段选择本地、远端或自定义值。任务的开始时间、截止时间、时区和全天状态是一组语义字段：界面不得因用户选择其中一项而替其他字段批量选择；合并后的整体必须在任何移动、创建或更新请求前通过校验，非法组合明确拒绝，不得静默折叠。
4. 提交前重新拉取远端；若再次变化，保留仍适用的选择并重开冲突。
5. 提交后重新拉取验证；只有验证成功才更新 Base、Local 并删除队列项。
6. 删除与修改、完成与重开、项目迁移、父子任务、检查事项和重复规则属于高风险冲突。
7. 应用冲突前必须持久原子认领为 `applying`，同一进程使用按冲突 ID 单飞；`applying` 期间禁止修改字段选择。远端结果未知时保持锁定，只有用户明确确认远端未发生写入后才能人工解锁，禁止重复创建。

## 4. 离线与恢复

- `data.json` 当前 schema 为 2。schema 1 升级时先用确切旧哈希验证快照，再换算 SHA-256；旧事件按语义生成新 ID 并去重，旧挑战领取补齐冻结规则。无法验证的旧数据进入只读恢复，不会被迁移“洗白”。
- 队列持久化且按数组中的持久位置保持同一对象的因果顺序；时间戳相同也不得越序。
- 队列只有一个活动消费者；所有状态转换基于存储中的最新队列原子修改，读取必须等待既有写链完成。
- 插件实例使用单调数据代际和跨重载全局写链：旧实例已开始的保存先完成，新实例再读取；代际失效后的旧保存一律拒绝。卸载后远端请求可以自然返回，但不得再持久化或通知 UI。
- 同一对象的冲突只冻结该对象；其他对象继续同步。
- 可安全合并连续更新，但不能越过创建、移动、完成或删除的因果边界。
- 创建请求超时后进入“待核对”，通过远端查询确认是否已创建；不得直接重试。
- 任何写操作在 `running` 状态中断，重启后都进入人工核对；远端删除后选择本地重建时，必须迁移新 ID、后续队列及 Helix 本地引用。
- 冲突选择删除后，主 Base/Local 缓存删除对应键；后续排队操作可使用只允许出现在队列 Base 中的 tombstone 作为因果基线，并保留任务清单上下文。
- 冲突写回停在 `applying` 时提供两个互斥人工路径：确认未写入后解锁重试；或复读远端并验证与已选结果一致后采纳。重建产生新 ID 时必须显式提供该 ID。
- 401、403、429、永久 4xx、5xx、网络错误和格式异常分别处理。
- 当前任务拉取使用全局过滤接口覆盖收集箱与开放任务，并补取近期已完成任务；仅当本轮声明的覆盖范围全部成功时，才在该范围内推断远端删除。未证实的分页能力不得写成“完整覆盖”。
- 已配置口令且开启自动同步时，插件启动后立即异步拉取一次，再注册周期定时器；保存新口令同样立即拉取。无关设置保存只重建定时器，不得制造额外远端读取。并发同步共享同一个在途 Promise，调用方不得在真实拉取完成前收到伪成功。
- 同步核心成功条件只有清单列表、开放任务和近期已完成任务均返回有效数组。单个清单详情只用于证明该清单的远端删除覆盖，失败时保留旧对象且不得阻断核心快照；习惯、打卡或专注失败时保留上次缓存并发布可见警告，也不得使清单与任务整批回滚。
- 演示数据只允许在“无口令、无任何真实滴答缓存且用户开启演示选项”时出现。有口令但未完成首次拉取必须显示等待或失败状态；有真实缓存但离线必须继续显示离线缓存，不能用演示数据覆盖。
- 设置页的“只读拉取测试”在排他远端访问门内执行，只调用读取语义接口并更新本地快照，绝不消费离线队列。普通任务写入、口令切换和合同测试在它结束前均不得取得远端访问权。
- 写入合同测试以本轮唯一标记创建两个临时清单和一条任务，启动前冻结既有清单 ID；删除只接受精确 ID、标记、归属和集合复读均匹配的测试对象。任务清理未获证明时禁止删除任何测试清单，合同运行期间普通远端写入和口令变更冻结。
- 任务更新属于非幂等写入：生产 API 遇到网络中断或 5xx 时只发送一次并分类为“远端结果未知”。合同随后只按本轮精确清单 ID、任务 ID 与唯一标记复读，并核对标题、内容、优先级、时区、全天状态及时间语义；全部匹配才视为已生效并继续，未生效、身份不符或复读失败均停止且明确报告阶段，禁止重发同一更新。
- 滴答任务日期写入统一使用公开接口约定的秒级 `yyyy-MM-dd'T'HH:mm:ssZ`，UTC 偏移写为 `+0000`；合同生成值先对齐整秒，复读按时间点比较。合同测试根据复读结果识别账号的任务时间能力：独立起止值均保留为 `duration`，开始值为空或被折叠为截止值则为 `point`，其他转换视为合同失败。
- 已验证的 `point`／`duration` 只作为授权上下文的能力缓存写入 `data.json`，不包含口令或口令摘要；缓存携带合同探针版本，编码或判定规则升级后旧版本自动失效。保存或清除 SecretStorage 口令必须通过服务的排他切换流程：先成功删除能力缓存，再改 SecretStorage；创建、更新、失败队列重试、同步、连接探测、任务身份复读、未知结果核对和冲突采纳等会读取或持久化远端事实的完整调用均持有共享授权租约，期间拒绝切换。`point` 模式只为原本就是单点的任务显示一个“任务时间”；若远端已有独立时间段，则以只读方式展示开始、截止、时区和全天状态，提交时直接复用远端原始值（包括秒和毫秒），允许修改其他字段但不得静默折叠。账号订阅或服务端能力变化后需要用户重新运行合同测试。
- 任务多视图只消费当前同步快照，不保存任务、日期分组、时间块、年度汇总或象限的影子真值。列表、日、3 日、周、月、年与四象限共用 `src/domain/task-views.ts`：周一为周首；进行中任务按起止区间覆盖所有相交日期；已完成任务按完成时间单日归档；定时任务按任务自身 `timeZone` 投影日期与显示钟点，缺失或非法时区才回退到设备时区；全天任务优先保留远端日期字面值，防止时区换算漂移；无日期与非法日期不进入日历和年度汇总，但仍保留在列表和四象限。
- 滴答看板与列表消费同一组任务快照，只有选中单一滴答清单时显示看板入口。列表／看板标签只切换 Helix 会话呈现；远端 `project.viewMode` 必须由独立的“设为滴答默认”动作显式提交，离线进入现有项目队列并显示待同步，权限拒绝、缓存过期、冲突或失败不得伪装为已同步。能力矩阵固定为：`project.viewMode` 公开接口可读写；`ProjectData.columns` 公开接口可读、未提供写端点；真实 V1 详情可观察到任务 `columnId`，但公开模型和写合同未声明；`task.sortOrder` 可读写但列内排序语义尚未验证。因此当前只允许：读取列、按真实 `columnId` 投影、未知归属进入“未分栏”、通过既有项目队列同步 `viewMode`。列新增/改名/删除/重排、跨列拖动和列内拖动必须保持禁用，直到专用对象合同完整证明写入与复读语义；不得接入需要账号密码的未公开 V2 会话接口，也不得保存 Helix 自建列真值。
- 看板列和 `taskColumnIds` 保存在 `data.json.boardSnapshots`，它们只是可由下一次完整 `ProjectData` 重建的只读远端缓存，不进入项目或任务 Base/Local/Remote 写对象。每项携带 `projectId`、最后成功 `capturedAt` 和 `stale`；某一清单详情失败或缺少显式 `columns` 时原子保留该清单上次列及任务归属、标记过期并禁止看板写入，不影响其他清单。重复列 ID、清单身份不符、空名、非法 `columnId` 或非法结构只降级对应清单。详情项目只验证身份并提供列/任务，名称、颜色、权限、默认视图和排序继续以全局项目列表为事实。
- 滴答真实 `sortOrder` 可能超过 JavaScript 安全整数。此时规范化只标记 `sortOrderUnsafe`，不使用可能失真的值排序，也不在普通任务编辑时回写；只读投影改用稳定 ID 兜底。只有后续合同获得无损表示并证明方向、间隔、碰撞与重排语义后才能开放排序写入。
- 时间块以任务自身时区的墙上时间绘制：全天与定时分层，缺少单侧时间、起止同一瞬间及完成记录统一投影为向后 15 分钟的单点块，跨日任务按每天切片；重叠块只在相交簇内分配泳道。夏令时跳跃和重叠按当地钟面位置稳定展示，不把显示时长反写为远端持续时间。
- 时间块已整合到日、3 日和月视图，不再保留并列的独立入口。日与 3 日调用同一个时间网格，月历调用同一个 `buildTaskTimeBlocks` 投影并显示定时任务的开始钟点；日期范围、任务区间、时区换算、单点规范化及重叠泳道只允许存在一份领域实现。UI 只能组合投影，不得复制算法、缓存派生任务集合或维护相互漂移的视图状态。
- 任务筛选是会话态。滴答清单作为一级导航只存在于侧栏；状态、标题/备注搜索和折叠式高级筛选位于同一工具层。高级筛选仅包含 Helix 项目、标签、精确优先级和日期，且可与当前滴答清单、状态及搜索叠加。搜索覆盖标题、内容、描述和检查项标题；日期筛选按任务区间与目标日期范围是否相交判定。同步快照不再包含选中清单、项目或标签时清除该会话条件，禁止界面显示“全部”但内部仍以消失值过滤。
- 快捷属性由唯一的 `src/domain/task-quick-entry.ts` 解析：`~清单`、`#标签` 和 `!高／!中／!低／!无` 只有在明确匹配时才从标题移除；含空格的清单名必须使用引号。未知清单、同名清单、多个不同清单、未知优先级或多个不同优先级均保留相应原文并阻止写入，不得静默择后。创建器必须在提交前显示解析后的标题和属性，并允许撤销解析、按普通标题处理；普通创建与任务编辑器共用该解析器。任务标题、清单、标签和优先级仍以滴答为真值，Helix 项目/阶段关联继续独立保存。
- 创建滴答清单必须进入既有离线队列、写后复读和冲突处理通道。名称先去除首尾空白并拒绝当前快照中的精确同名，颜色仅接受 `#RRGGBB`；网络或 5xx 的结果未知不得盲目重发。`local-project-*` 只表示创建结果尚未取得远端身份：侧栏可显示并进入冲突中心核对，但任务创建器和任务编辑器必须排除它；服务入口必须在任何快照或队列写入前拒绝新任务或已有任务引用。若异常旧任务当前已引用该 ID，编辑器只读显示当前值并冻结任务保存。确认远端 ID 并完成同步刷新后才允许作为任务清单。当前不建立跨对象离线依赖，因此不存在把任务队列静默迁移到新清单 ID 的路径。侧栏只把清单作为任务导航，不复制清单或任务为 Helix 项目事实。
- 未来项目联动的候选边界是“一个 Helix 项目显式绑定一个稳定滴答清单 ID，项目行动显式绑定滴答任务/子任务 ID”。在项目和任务两条工作流各自达到完整可用前不得自动创建绑定；不得用标题匹配、目录位置或 Canvas 坐标推断。绑定仍需保持 Markdown/Canvas 与滴答各自权威，并在竞争时进入人工逐字段合并。
- 四象限每项任务都以同一当前时刻在自身时区的“今天”判断紧急性，不受设备日期线差异及日历导航锚点影响，完成任务不进入象限。重要优先级阈值和紧急天数属于 `HelixSettings` 中的本地显示规则，只能通过串行设置通道持久化；必须先保存成功再发布运行时，规则变化不得改写滴答任务真值。

## 5. Markdown 与 Canvas 安全

- 写入前记录文件哈希；提交时哈希变化则停止并提示冲突。
- Markdown 只维护 `helix-*` 属性和标记清晰的自动摘要块，保留正文、未知属性、BOM 与换行风格。
- 项目 Markdown 是项目身份、名称、状态和正文的唯一事实；阶段 Markdown 是阶段身份、所属项目、状态和正文的唯一事实。活动阶段由各阶段的 `helix-status` 派生，允许同项目内多个 `active`。
- 任务关联使用独立的 `helix-kind: helix-task-reference` Markdown，每份只保存关联 UUID、`provider=dida`、已确认的滴答远端任务 ID、一个 Helix 项目 ID、零到多个阶段 ID 以及创建/更新时间。任务标题、状态、内容、时间、优先级和滴答清单不得复制进关联文件或 `data.json`；项目/阶段 Wikilink 只是可重建的 Obsidian 反向链接投影。
- 任务字段与 Helix 关联属于两个权威域，任务弹窗提供独立保存动作。只改关联不得创建滴答同步队列；只改滴答字段不得重写关联 Markdown，也不得把其中一个动作的成功显示成两侧整体成功。
- 只有已取得远端 ID 的任务可以建立关联；`local-*` 临时任务禁止成为关联真值。任务移动清单、完成或暂时不在同步覆盖范围内时保留关联；远端删除不级联删除关联。任务被人工重建成新 ID 时，只允许用户明确核验后重绑，禁止按标题或时间猜测；提交前还必须按新任务 ID 与滴答清单实时复读，并核对远端返回身份一致。
- 关联保存必须用弹窗打开时的关联 UUID 与 Markdown revision 做比较；文件在提交前变化、同一任务出现多份关联、关联 UUID 重复或结构损坏时停止写入。项目/阶段删除或阶段改属其他项目时保留原 ID 并显示断链，用户可以明确重新绑定或解除，不静默清理。
- 项目与阶段状态编辑只允许在对应 Markdown revision 未变化时更新 `helix-status` 与 `helix-updated`；不得重写用户正文、未知 frontmatter 或用 Canvas 摘要反向覆盖 Markdown。Canvas 中的标题和状态摘要只是派生缓存，由下一次 `ensureCanvas` 校验按 Markdown 真值修复。
- 新阶段文件使用 `Stage-XX.md`；一级标题为 `阶段 X · 自拟标题`，新元数据使用 `helix-kind: helix-stage`。
- 专用 Canvas 是项目/阶段节点布局和阶段关系的唯一事实；`data.json` 不保存项目、阶段、关系或布局副本。
- 托管项目节点必须包含 `helixManaged=true`、`helixNodeKind=project`、`helixProjectId`；新托管阶段节点使用 `helixNodeKind=stage`、`helixStageId` 和所属 `helixProjectId`。旧 `helix-kind: helix-cycle`、`helixNodeKind=cycle`、`helixCycleId` 与 `Cycle-XX.md` 仅兼容读取，不静默改名。身份必须与对应 Markdown 唯一匹配。
- 托管物理边只允许阶段指向阶段，并且是唯一结构事实。`helixRelation` 是全图正规化后的显示分类：若目标入度不少于 2，则目标的全部入边为合并；否则若来源出度不少于 2，则来源的全部非合并出边为分支；其余为继承。合并组必须覆盖同一目标的全部入边，`helixMergeGroupId` 由目标阶段 ID 稳定生成。拒绝自环、重复边、悬空节点和有向环。
- 无标签边、非托管边、未知节点、未知 JSON 字段和用户布局原样保留，不自动解释。普通原生边只有在两个端点均为已识别阶段时才显示为候选；用户必须逐条确认，跨项目还需独立勾选。提交重新核对候选 `edgeId`、物理端点和 Canvas revision，并执行自环、重复和 DAG 校验；通过后只为该边增加托管及派生关系字段，保留未知字段。
- 跨项目阶段关系允许，但创建前必须显示来源项目并明确确认。
- 旧 `helix-parents`、`helix-active-cycle`、`helix-predecessor` 和 `derives-from` 边不得自动转换。Helix 必须逐项展示来源和处理方式；取消时零写入。用户可确认保留旧数据而不推断关系。
- 新建阶段的 Markdown 与 Canvas 节点/边按一个计划写入。Canvas 比较写入失败时，将本轮新建且未被用户改动的文件移入仓库 `.trash`；回滚遇到竞争则停止后续写入并报告。
- 阶段卡片右侧加号是创建关系的语义入口，不再重复询问关系类型和前置阶段。单卡加号在来源没有后继时创建继承；再次从已有后继的来源点击加号时创建或扩展分支，并把原有单一继承边转换为分支。用户点击具体来源卡片的加号即为对该派生动作的明确确认。
- 关系图中多选两个及以上阶段后，点击其中任一卡片的加号会以全部所选阶段为前置创建合并节点，来源顺序取当前拖动后的画布位置。若某个来源已有继承后继，该继承边会在摘要中预告并随本次提交改为分支，从而保持 DAG 关系合法。跨项目所选仍要求单独确认，并明确显示新阶段归属的被点击卡片所属项目及外部来源；已有关系的其他修改继续通过关系管理入口完成。
- 自动创建必须携带弹窗展示时的完整预期意图，包括关系类型和需要转换的继承边 ID。服务提交时从 Canvas 快照重新推断并逐项比较；用于推断的 Canvas 哈希还必须与后续写入的 revision 一致。任一变化都在创建 Markdown 前拒绝，禁止按过期语义静默提交。
- 结构变化默认只整理受影响的弱连通分量；同项目内不在该分量的阶段和项目兼容锚点必须保持原坐标，容器避让也只能整体平移范围内阶段，不得借机扩大成整项目重排。全图整理必须由用户显式点击“整理全部”。仅 Helix 托管节点参与：项目为第 0 层、无前驱阶段为第 1 层、其他阶段为 `1 + max(前驱层)`；项目泳道、同层分支和 ID 使用稳定排序。泳道高度按项目在同一拓扑深度上的最大行数计算，不得按阶段总数把横向节点错误换算成纵向空白。跨项目合并留在目标项目泳道，非托管节点永不移动。整理完成后，前端必须以平滑滚动把新建阶段、连线来源、关系目标或删除后的邻近实体移回视口中心，并提供短暂的非颜色唯一高亮；不得让结构操作后视点停在旧空白位置。折叠只影响投影，不改变物理节点、边和坐标。
- Canvas 内维护每个项目的阶段序号高水位；删除或恢复旧阶段不会回退高水位，新阶段不得复用已删除的 `Stage-XX.md` 路径。
- 删除阶段必须明确确认。删除 V 时可选择以 `predecessors(V) × successors(V)` 桥接路径；已存在边复用，禁止重复边。计划必须分别冻结桥接与不桥接两套受影响节点，以及每条旧边的 `edgeId`、原类型和新类型；弹窗随开关显示当前模式的新增、复用、跨项目、精确重标清单和布局节点数。新增候选超过 24 条时禁止一键全桥接并使用不桥接口径。跨项目桥接另行确认。完整计划先做 DAG 校验，并与布局、正规化结果一起进入同一 Canvas after 镜像。
- 删除提交先用 Canvas 版本比较写入完整 after 镜像，再仅在 Markdown 原路径存在且哈希未变时移入仓库 `.trash`；Markdown 被并发改名或删除时视为冲突，并用刚写入的 Canvas 版本执行回滚，回滚再竞争则冻结并要求人工检查。项目唯一阶段不得删除。
- 已有关系允许在内嵌画布中选择、调整来源和删除。继承、分支、合并不是独立可编辑真值，始终由完整物理边集的入度与出度重算。关系更改只触碰明确的 Helix 托管边；每次提交前重新验证来源、跨项目确认和 DAG，竞争时拒绝覆盖。
- 项目页是内嵌的 Canvas 式前端：关系图、卡片和看板均从 Markdown/Canvas 即时读取。关系图不把项目渲染成与阶段同级的普通节点；它按该项目当前可见阶段的 Canvas 坐标计算一个底层自适应容器，使用项目色的单一透明填充而非渐变，容器标题打开项目 Markdown，并承载项目状态与完成折叠入口。项目托管节点仍作为原生 Canvas 的兼容身份锚点保留，不因前端容器投影而删除、改型或成为第二份项目真值。阶段卡片只是摘要和入口，点击后打开对应 Markdown。
- 项目颜色只接受规范 `#RRGGBB` 或空值，通过项目 Markdown 的哈希比较写入；颜色只作项目区分，完成状态必须同时使用绿色勾选和文字，不得仅依赖颜色。
- 项目选择是会话态：关系图保留全局 DAG 并弱化未选项目，卡片和看板按选择真实过滤，必须提供“全部项目”。项目胶囊内包含独立调色入口；点击项目标签必须以该项目容器外框为目标，同时计算可放大或缩小的适应比例，并在同一相机动画中插值逻辑中心与缩放；点击“全部项目”以所有容器的内容边界恢复全局适应。结构操作保持当前缩放并聚焦具体阶段。选择和相机状态不写入 Canvas。
- 空白左键拖动用于矩形框选当前投影中的可见阶段，卡片显示盒与选择矩形相交即命中；普通框选替换选择，Shift 框选追加选择，单击空白清空。空格加左键和鼠标中键的平移优先级高于框选；卡片拖动、关系把手和所有按钮不启动框选。Escape、`pointercancel` 或失去指针捕获必须恢复框选开始前的选择；折叠隐藏节点与项目兼容锚点不得进入结构选择。框选是会话态，命中计算保持对可见节点的一次线性扫描。
- 完成折叠只持久化版本化的项目 ID 集合。每个项目内 `closed` 阶段诱导子图的最大弱连通分量（至少两个节点）分别折叠成纯投影头；不允许跨越 active/planned 阶段把互不连续的完成节点强行合成，否则会伪造物理 DAG 不存在的视觉环。隐藏节点、边和坐标不删除，外部关系以不可编辑聚合边显示，点击聚合边或头节点摘要先展开。该投影不得进入创建、拖动、批量选择或关系编辑的结构输入。
- 内嵌画布“无限”定义为实践上无边界：Canvas 原始坐标是唯一事实；屏幕 origin 和四向动态扩边仅存在于内存，并在左/上扩边时补偿滚动位置，不批量改写节点坐标。每次四向扩边必须按当前缩放换算出稳定的屏幕余量，低缩放时不得因不足 1px 的补偿形成连续扩边循环。坐标必须有限且位于安全范围，适应全部按项目容器的逻辑边界计算。按钮、触控板和快捷缩放都保持缩放前的逻辑视口中心；结构操作后的聚焦动画是会话态，不写入 Canvas。项目标签和双击阶段卡片都按目标外框计算比例并居中聚焦，最大缩放统一为 120%；卡片内打开、创建、连接和删除按钮保持原语义，不触发双击相机导航。相机过渡默认 420ms，缩放与逻辑中心使用同一缓动进度；`prefers-reduced-motion: reduce` 下必须无动画跳转。
- 多卡移动必须在一次 Canvas 比较写入中提交。检测到竞争时回滚屏幕上的临时位置并提示用户，禁止并发逐卡写入或吞掉错误。
- 阶段删除不是跨文件原子事务，因此在 Canvas CAS 之前必须先创建内部日志 `Helix/.transactions/stage-delete.json`。隐藏目录和未注册扩展名不会稳定进入 Obsidian 的 `TFile` 索引，仓库层必须在索引缺失时回退到 Vault adapter 读取并校验原始内容；清理时优先使用仓库废纸篓，未索引的机器日志则在再次核对内容哈希后直接移除。日志保存阶段身份、原路径和哈希，以及 Canvas 写入前/后的完整内容与哈希；任一时刻只允许一个阶段删除事务。成功删除或完整回滚后必须清理日志。
- 插件启动时先恢复未完成的阶段删除：Canvas 仍为旧版本且 Markdown 保留时撤销未开始的事务；Canvas 已为新版本且 Markdown 未变时继续移入废纸篓；Markdown 已删除时确认完成；Markdown 被修改或改名时仅以新 Canvas 哈希为前提回滚；Canvas 同时出现未知版本时冻结项目工作区并要求人工检查。日志内容、路径或哈希损坏时同样冻结，禁止猜测或静默覆盖。
- 项目图谱提供会话级撤销/重做，最多保留 50 项且总镜像不超过 5 MiB；不把历史写入 `data.json`。移动、连接、关系修改、整理与折叠保存精确 Canvas 前后内容；新建或删除项目/阶段还保存 Markdown 路径、稳定身份和前后内容。应用跨文件历史前先写入唯一临时日志 `Helix/.transactions/workspace-history.json`，再创建所需 Markdown、以 Canvas revision 原子提交、最后删除不再需要的 Markdown；成功后清理日志。启动恢复只接受 Canvas 处于事务起点或终点，其他版本、身份漂移、路径占用、同时存在阶段删除日志或外部修改都冻结工作区，不猜测顺序。
- 所有项目结构写入、撤销、重做与可能修复 Canvas 的读取入口共用串行命令通道。普通 Markdown/Canvas 比较写入使用 `Vault.process` 在原子回调内核对内容哈希；用户文件和未索引机器日志删除都先原子改名为确定性的 `.helix-delete-claim`，在认领路径再次复核内容哈希，不变才移入仓库废纸篓或移除；竞争及删除失败恢复原路径并报告冲突。插件启动必须先递归恢复认领文件，再恢复撤销或阶段删除事务；若原路径已被占用则保留认领文件并冻结，禁止覆盖。拖动操作还必须绑定界面开始拖动时看到的 Canvas revision。任何无法与历史顶端镜像对应的外部 Canvas 修改都会清空会话历史，撤销本身则在 revision 或 Markdown 身份变化时解释性拒绝。
- 项目页启用写操作前必须连续读取两个语义一致且 Canvas revision 相同的快照；同步产生的短暂无效 JSON、身份不完整或前后变化只允许有限重试。稳定快照与修复提交之间 Canvas 再变化时零写入拒绝；缺失 Canvas 必须排他创建，目标在创建前出现即冲突，不得再次读取后接管；连续失败时显示最后一次有效快照的只读 Markdown 入口，不得用旧快照写回。项目和阶段 Markdown 以稳定 ID 全库发现，成功快照维护路径索引，使文件移出默认项目目录后仍可监听修改、删除和重命名；未知外部 Markdown 的新建与修改需去抖检查项目身份，覆盖空文件建立后再填充 frontmatter 的同步写法。
- 删除阶段前必须检查所有相连边；若存在原生 Canvas 非托管边，默认拒绝删除并要求用户先移除或显式纳管，禁止按端点静默删除用户关系。
- `data.json` 集合、事件类型载荷与确定性 ID、快照哈希与实体 ID、队列对象/操作类型、由三方快照重算的冲突字段、审计及进行中标记在载入时做结构校验；集合 ID、事件语义和正在进行任务不得重复，阻塞队列必须引用同一对象的真实冲突。损坏条目不会参与同步，插件进入禁止写入的恢复模式，并在冲突中心显示问题及脱敏诊断。

## 6. 分析与挑战

- 事件必须具备基于 SHA-256 的确定性 `eventId` 并按语义去重。Helix 发起且经远端验证成功的任务完成操作必须立即入账，不依赖 31 天补拉窗口。
- 重复任务按 occurrence 计奖；任务重开、习惯撤销与专注记录删除会回收对应统计、奖励和挑战进度。
- XP、等级、徽章、热力图和趋势图全部由事件重算；挑战达标事件冻结当期指标、目标、周期边界、奖励和规则版本，后续 Release 修改挑战池不会篡改历史奖励。任务重开或专注删除使冻结口径下的进度跌破目标时不再计入奖励。
- 默认使用正向鼓励；压力和严格模式为显式可选。
- 周/月挑战由本地确定性轮换生成，新主题随插件 Release 更新，不依赖后端推送。
- 任务完成、复盘关闭等本地事件统一经过“追加事件→重新评估挑战→刷新运行时”入口，达标奖励无需等待下一次滴答全量同步。

## 7. 已知外部限制

- 滴答公开更新接口尚未证实支持 `If-Match` 原子条件写入。未通过真实合同测试前，只承诺 Helix 自身不静默合并，并采用写前/写后验证缩小竞态窗口。
- Obsidian Sync 不向插件公开任意 Markdown 的服务器三方版本。Helix 可以保护自身结构化写入并冻结冲突，但不能替代 Obsidian 对普通用户正文的文件级冲突处理。
- 当前私测版只承诺单一设备编辑 Task Reference；其他设备可继续通过滴答编辑任务。运行中 revision 比较能拒绝竞争覆盖，但插件关闭期间的同步器最后写入无法构造 Base/Local/Remote 三方版本。发布前若要承诺多设备编辑 Helix 关联，必须升级为不可变修订/双头检测并在 Helix 内逐字段合并。
