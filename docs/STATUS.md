## 本轮目标

- 远端完成／重新打开项目子任务后，自动安全更新 Stage Markdown、任务页和父任务派生状态，同时保持 Helix 可操作。
- 非目标：不清理用户滴答数据，不修改无关正式 Vault 文件，不合并 `main`、不打标签、不发布 Release。

## 当前事实

- Project／Stage Markdown 是项目身份、状态、正文与本地任务的权威源；专用 Canvas 是关系和布局的权威源。
- Stage 父任务状态直接来自 Stage；父任务完成状态由直属子任务派生，不能手动完成。
- 正向项目投影和反向完成状态均复用现有任务管线、投影账本、CAS 与逐字段冲突机制。
- 滴答清单详情只覆盖活动任务；反向同步将普通拉取缓存中的已完成任务与清单详情合并，同 ID 以详情为准以支持重新打开。
- 父任务冻结只阻止远端写入；身份已验证的子任务状态仍可安全回写 Markdown。远端父任务重新符合 Helix 期望时会清除无待处理记录的幽灵冻结。
- 项目远端同步使用独立串行器，不再持有项目工作区 mutation runner；同一项目的多个 Stage 共用一次目标清单目录读取。
- 自动同步候选指纹包含已纳管远端任务状态；普通滴答拉取完成并释放授权锁后会重新计算项目同步就绪条件。
- 正式 Vault 的自动项目投影已启用，目标为既有 `Helix Projects`；ATEC 2026 Stage-04 有 1 个父任务和 7 个行动远端 ID。
- `2.1.1` 是当前已发布版本；日常开发只在 `dev`，只有用户明确要求发布时才允许合入 `main`。

## 本轮改动

- `dida-project-projection`：增加批量目录复用、远端完成／重开三方合并、分 Stage 单次 CAS 回写、父任务冻结下的只读子任务对账及幽灵冻结收口。
- `helix-service`：项目目录复用清单详情任务，并合并普通同步缓存中的已完成任务；活动详情优先覆盖同 ID 缓存。
- `main`：项目同步改用独立 runner；远端状态加入候选指纹；普通拉取完成后延迟到授权锁释放再唤醒项目协调器。
- 测试覆盖远端完成、远端重开、状态竞争、父任务冻结、幽灵冻结、批量目录复用、完成缓存与活动详情覆盖。
- 正式 Vault 仅部署插件构建，并由同步逻辑把 ATEC Stage-04 的 5 条远端完成状态回写到 Helix 管理复选框和标记。

## 相关约束

- 权威边界、本地任务投影与滴答合同见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 3、5 节。
- 合同测试只操作唯一标记的专用临时对象；远端结果未知或清理未证实时保持只读，禁止盲目重试。
- 远端与本地从同一 Base 发生竞争时必须进入逐字段冲突，不允许静默覆盖。
- 正式 Vault 只允许本需求明确授权的同步回写；其他用户文件和滴答对象不得用于测试或清理。
- API 口令只存 SecretStorage；换设备、Vault、授权或合同版本均需重新验证。
