# 架构与边界

本文件定义 Helix 的长期架构、权威数据边界、核心数据流和必须显式处理的边界情况。实现发生结构变化时更新本文件；日常进度不写在这里。

## 1. 权威数据边界

| 数据 | 权威端 | Helix 行为 |
| --- | --- | --- |
| 任务、远端清单 | 滴答清单 | 缓存、编辑、离线排队、显式冲突合并 |
| 习惯定义与打卡 | 滴答清单 | 可在 Helix 新建、编辑和打卡，远端记录为最终事实 |
| 专注记录 | 滴答清单 | 导入各设备记录，Helix 计时完成后回写 |
| 项目身份、名称、状态、颜色与正文 | 项目 Markdown | Helix 发现、创建、打开和安全写入 |
| 阶段身份、所属项目、状态与正文 | 阶段 Markdown | 自动编号“阶段 X”，标题由用户自拟；支持多个 `active` 阶段 |
| 日周月年复盘 | Helix Markdown | 模板生成、数据辅助、用户回答 |
| 阶段关系与布局 | 唯一主 Canvas | 只解释明确托管的继承、分支、合并边并强制 DAG |
| “正在进行” | Helix | 不写入滴答标签；首页显示前三项并可展开 |
| 统计、XP、成就、挑战 | Helix 事件账本派生 | 不以可变累计值作为唯一事实 |

## 2. 模块结构

- `src/integrations/dida`：HTTP、能力探测、正规化及任务/项目/习惯/专注适配器。
- `src/sync`：Base 快照、离线操作、三方差异、冲突解决、写前复查与写后验证。
- `src/domain`：项目、阶段、复盘、Canvas DAG、事件、分析、XP 与挑战。
- `src/storage`：SecretStorage、插件持久状态、Markdown/Canvas 安全读写。
- `src/ui`：Obsidian ItemView 和界面组件，只调用服务接口。

## 3. 同步状态机

每个远端对象维护：

- Base：上次已验证同步版本，含数据、`etag`、修改时间和正规化 SHA-256 哈希。
- Local：Helix 当前本地版本。
- Remote：本轮同步新拉取版本。

规则：

1. 仅一端相对 Base 变化时可以自动同步。
2. 两端都变化且结果不同，暂停整个对象并建立冲突；即使变化发生在不同字段，也必须由用户确认后提交。
3. 用户逐字段选择本地、远端或自定义值。日期、重复、时区和提醒作为关联字段组处理。
4. 提交前重新拉取远端；若再次变化，保留仍适用的选择并重开冲突。
5. 提交后重新拉取验证；只有验证成功才更新 Base、Local 并删除队列项。
6. 删除与修改、完成与重开、项目迁移、父子任务、检查事项和重复规则属于高风险冲突。
7. 应用冲突前必须持久原子认领为 `applying`，同一进程使用按冲突 ID 单飞；`applying` 期间禁止修改字段选择。远端结果未知时保持锁定，只有用户明确确认远端未发生写入后才能人工解锁，禁止重复创建。

## 4. 离线与恢复

- `data.json` 当前 schema 为 2。schema 1 升级时先用确切旧哈希验证快照，再换算 SHA-256；旧事件按语义生成新 ID 并去重，旧挑战领取补齐冻结规则。无法验证的旧数据进入只读恢复，不会被迁移“洗白”。
- 队列持久化且按数组中的持久位置保持同一对象的因果顺序；时间戳相同也不得越序。
- 队列只有一个活动消费者；所有状态转换基于存储中的最新队列原子修改，读取必须等待既有写链完成。
- 插件实例使用单调数据代际和跨重载全局写链：旧实例已开始的保存先完成，新实例再读取；代际失效后的旧保存一律拒绝。卸载后远端请求可以自然返回，但不得再持久化或通知 UI。
- 同一对象的冲突只冻结该对象；其他对象继续同步。
- 可安全合并连续更新，但不能越过创建、移动、完成或删除的因果边界。
- 创建请求超时后进入“待核对”，通过远端查询确认是否已创建；不得直接重试。
- 任何写操作在 `running` 状态中断，重启后都进入人工核对；远端删除后选择本地重建时，必须迁移新 ID、后续队列及 Helix 本地引用。
- 冲突选择删除后，主 Base/Local 缓存删除对应键；后续排队操作可使用只允许出现在队列 Base 中的 tombstone 作为因果基线，并保留任务清单上下文。
- 冲突写回停在 `applying` 时提供两个互斥人工路径：确认未写入后解锁重试；或复读远端并验证与已选结果一致后采纳。重建产生新 ID 时必须显式提供该 ID。
- 401、403、429、永久 4xx、5xx、网络错误和格式异常分别处理。
- 当前任务拉取使用全局过滤接口覆盖收集箱与开放任务，并补取近期已完成任务；仅当本轮声明的覆盖范围全部成功时，才在该范围内推断远端删除。未证实的分页能力不得写成“完整覆盖”。

## 5. Markdown 与 Canvas 安全

- 写入前记录文件哈希；提交时哈希变化则停止并提示冲突。
- Markdown 只维护 `helix-*` 属性和标记清晰的自动摘要块，保留正文、未知属性、BOM 与换行风格。
- 项目 Markdown 是项目身份、名称、状态和正文的唯一事实；阶段 Markdown 是阶段身份、所属项目、状态和正文的唯一事实。活动阶段由各阶段的 `helix-status` 派生，允许同项目内多个 `active`。
- 新阶段文件使用 `Stage-XX.md`；一级标题为 `阶段 X · 自拟标题`，新元数据使用 `helix-kind: helix-stage`。
- 专用 Canvas 是项目/阶段节点布局和阶段关系的唯一事实；`data.json` 不保存项目、阶段、关系或布局副本。
- 托管项目节点必须包含 `helixManaged=true`、`helixNodeKind=project`、`helixProjectId`；新托管阶段节点使用 `helixNodeKind=stage`、`helixStageId` 和所属 `helixProjectId`。旧 `helix-kind: helix-cycle`、`helixNodeKind=cycle`、`helixCycleId` 与 `Cycle-XX.md` 仅兼容读取，不静默改名。身份必须与对应 Markdown 唯一匹配。
- 托管物理边只允许阶段指向阶段，并且是唯一结构事实。`helixRelation` 是全图正规化后的显示分类：若目标入度不少于 2，则目标的全部入边为合并；否则若来源出度不少于 2，则来源的全部非合并出边为分支；其余为继承。合并组必须覆盖同一目标的全部入边，`helixMergeGroupId` 由目标阶段 ID 稳定生成。拒绝自环、重复边、悬空节点和有向环。
- 无标签边、非托管边、未知节点、未知 JSON 字段和用户布局原样保留，不自动解释。
- 跨项目阶段关系允许，但创建前必须显示来源项目并明确确认。
- 旧 `helix-parents`、`helix-active-cycle`、`helix-predecessor` 和 `derives-from` 边不得自动转换。Helix 必须逐项展示来源和处理方式；取消时零写入。用户可确认保留旧数据而不推断关系。
- 新建阶段的 Markdown 与 Canvas 节点/边按一个计划写入。Canvas 比较写入失败时，将本轮新建且未被用户改动的文件移入仓库 `.trash`；回滚遇到竞争则停止后续写入并报告。
- 阶段卡片右侧加号是创建关系的语义入口，不再重复询问关系类型和前置阶段。单卡加号在来源没有后继时创建继承；再次从已有后继的来源点击加号时创建或扩展分支，并把原有单一继承边转换为分支。用户点击具体来源卡片的加号即为对该派生动作的明确确认。
- 关系图中多选两个及以上阶段后，点击其中任一卡片的加号会以全部所选阶段为前置创建合并节点，来源顺序取当前拖动后的画布位置。若某个来源已有继承后继，该继承边会在摘要中预告并随本次提交改为分支，从而保持 DAG 关系合法。跨项目所选仍要求单独确认，并明确显示新阶段归属的被点击卡片所属项目及外部来源；已有关系的其他修改继续通过关系管理入口完成。
- 自动创建必须携带弹窗展示时的完整预期意图，包括关系类型和需要转换的继承边 ID。服务提交时从 Canvas 快照重新推断并逐项比较；用于推断的 Canvas 哈希还必须与后续写入的 revision 一致。任一变化都在创建 Markdown 前拒绝，禁止按过期语义静默提交。
- 结构变化默认只整理受影响的弱连通分量；全图整理必须由用户显式点击“整理全部”。仅 Helix 托管节点参与：项目为第 0 层、无前驱阶段为第 1 层、其他阶段为 `1 + max(前驱层)`；项目泳道、同层分支和 ID 使用稳定排序。跨项目合并留在目标项目泳道，非托管节点永不移动。折叠只影响投影，不改变物理坐标。
- Canvas 内维护每个项目的阶段序号高水位；删除或恢复旧阶段不会回退高水位，新阶段不得复用已删除的 `Stage-XX.md` 路径。
- 删除阶段必须明确确认。删除 V 时可选择以 `predecessors(V) × successors(V)` 桥接路径；已存在边复用，禁止重复边。计划必须分别冻结桥接与不桥接两套受影响节点，以及每条旧边的 `edgeId`、原类型和新类型；弹窗随开关显示当前模式的新增、复用、跨项目、精确重标清单和布局节点数。新增候选超过 24 条时禁止一键全桥接并使用不桥接口径。跨项目桥接另行确认。完整计划先做 DAG 校验，并与布局、正规化结果一起进入同一 Canvas after 镜像。
- 删除提交先用 Canvas 版本比较写入完整 after 镜像，再仅在 Markdown 原路径存在且哈希未变时移入仓库 `.trash`；Markdown 被并发改名或删除时视为冲突，并用刚写入的 Canvas 版本执行回滚，回滚再竞争则冻结并要求人工检查。项目唯一阶段不得删除。
- 已有关系允许在内嵌画布中选择、调整来源和删除。继承、分支、合并不是独立可编辑真值，始终由完整物理边集的入度与出度重算。关系更改只触碰明确的 Helix 托管边；每次提交前重新验证来源、跨项目确认和 DAG，竞争时拒绝覆盖。
- 项目页是内嵌的 Canvas 式前端：关系图、卡片和看板均从 Markdown/Canvas 即时读取。卡片只是摘要和入口，点击后打开对应 Markdown；不把卡片内容当成第二份笔记。
- 项目颜色只接受规范 `#RRGGBB` 或空值，通过项目 Markdown 的哈希比较写入；颜色只作项目区分，完成状态必须同时使用绿色勾选和文字，不得仅依赖颜色。
- 项目选择是会话态：关系图保留全局 DAG 并弱化未选项目，卡片和看板按选择真实过滤，必须提供“全部项目”。选择状态不写入 Canvas。
- 完成折叠只持久化版本化的项目 ID 集合。每个项目内 `closed` 阶段诱导子图的最大弱连通分量（至少两个节点）分别折叠成纯投影头；隐藏节点、边和坐标不删除，外部关系以不可编辑聚合边显示，点击聚合边先展开。
- 内嵌画布“无限”定义为实践上无边界：Canvas 原始坐标是唯一事实；屏幕 origin 和四向动态扩边仅存在于内存，并在左/上扩边时补偿滚动位置，不批量改写节点坐标。每次四向扩边必须按当前缩放换算出稳定的屏幕余量，低缩放时不得因不足 1px 的补偿形成连续扩边循环。坐标必须有限且位于安全范围，适应全部按逻辑内容边界计算。
- 多卡移动必须在一次 Canvas 比较写入中提交。检测到竞争时回滚屏幕上的临时位置并提示用户，禁止并发逐卡写入或吞掉错误。
- 阶段删除不是跨文件原子事务，因此在 Canvas CAS 之前必须先创建 `Helix/.transactions/stage-delete.json`。日志保存阶段身份、原路径和哈希，以及 Canvas 写入前/后的完整内容与哈希；任一时刻只允许一个阶段删除事务。成功删除或完整回滚后把日志移入仓库废纸篓。
- 插件启动时先恢复未完成的阶段删除：Canvas 仍为旧版本且 Markdown 保留时撤销未开始的事务；Canvas 已为新版本且 Markdown 未变时继续移入废纸篓；Markdown 已删除时确认完成；Markdown 被修改或改名时仅以新 Canvas 哈希为前提回滚；Canvas 同时出现未知版本时冻结项目工作区并要求人工检查。日志内容、路径或哈希损坏时同样冻结，禁止猜测或静默覆盖。
- `data.json` 集合、事件类型载荷与确定性 ID、快照哈希与实体 ID、队列对象/操作类型、由三方快照重算的冲突字段、审计及进行中标记在载入时做结构校验；集合 ID、事件语义和正在进行任务不得重复，阻塞队列必须引用同一对象的真实冲突。损坏条目不会参与同步，插件进入禁止写入的恢复模式，并在冲突中心显示问题及脱敏诊断。

## 6. 分析与挑战

- 事件必须具备基于 SHA-256 的确定性 `eventId` 并按语义去重。Helix 发起且经远端验证成功的任务完成操作必须立即入账，不依赖 31 天补拉窗口。
- 重复任务按 occurrence 计奖；任务重开、习惯撤销与专注记录删除会回收对应统计、奖励和挑战进度。
- XP、等级、徽章、热力图和趋势图全部由事件重算；挑战达标事件冻结当期指标、目标、周期边界、奖励和规则版本，后续 Release 修改挑战池不会篡改历史奖励。任务重开或专注删除使冻结口径下的进度跌破目标时不再计入奖励。
- 默认使用正向鼓励；压力和严格模式为显式可选。
- 周/月挑战由本地确定性轮换生成，新主题随插件 Release 更新，不依赖后端推送。
- 任务完成、复盘关闭等本地事件统一经过“追加事件→重新评估挑战→刷新运行时”入口，达标奖励无需等待下一次滴答全量同步。

## 7. 已知外部限制

- 滴答公开更新接口尚未证实支持 `If-Match` 原子条件写入。未通过真实合同测试前，只承诺 Helix 自身不静默合并，并采用写前/写后验证缩小竞态窗口。
- Obsidian Sync 不向插件公开任意 Markdown 的服务器三方版本。Helix 可以保护自身结构化写入并冻结冲突，但不能替代 Obsidian 对普通用户正文的文件级冲突处理。
