## 当前事实

- Project／Stage Markdown 是项目内容权威源，专用 Canvas 保存关系与布局；`data.json` 只保存恢复和同步状态。
- Stage `# 计划行动` 顶层条目进入任务页，缩进条目为本地子任务。
- 滴答能力按只读、普通写入、专用合同、项目投影分层；默认关闭，启用须版本化二次确认。
- 普通任务 CRUD、跨清单移动、完成／重开、冲突和父子关系已有自动化及 v12 合同证据。
- Local 与 Remote 相同时直接推进 Base、清理队列且零重复写入；中断写入重启后进入结果未知，自动同步不得重发。
- 连接使用 unknown／online／offline 三态；仅 transient 读取失败进入 offline，离线编辑只排队，成功同步后再消费。
- 离线时冲突字段选择仍可保存为 staged，但应用在任何远端读取或 applying 认领前拒绝。
- 离线时未知写入与冲突采纳保持冻结且零远端访问；跨清单移动仅在源或目标唯一可见时恢复。
- 限流状态持久化；冲突中心显示截止时间，到期后只允许一次受控读取，成功前不消费写队列。
- 项目映射为稳定 marker 父 Task；Stage 行动映射为带 `parentId` 和 marker 的子 Task，不使用 `items`。
- 项目删除经队列精确删除远端子任务及父任务；持久 tombstone 阻止未知结果重发和删除失败后的复活。
- 结果未知禁止重发；字段竞争保存 Base／Local／Remote，必须人工处理。
- 版本 `1.0.1`，最低 Obsidian `1.12.2`；当前不发布。

## 本轮改动

- 普通任务支持一致结果零写收敛、重启未知冻结、离线排队及恢复后消费。
- 未知创建要求完整字段匹配；跨清单移动须源／目标唯一可见，歧义时冻结。
- 冲突应用与未知恢复在离线时零远端访问；冲突中心显示脱敏限流状态。
- schema 1 未知写入迁移后仍保留 `reconciliation`、尝试次数和未知标记；旧未版本化项目投影保持禁用。
- Vault 投影同步纳入自写 quiet-window，避免 Markdown 回填被自身监听误判为竞争。
- 后台同步要求投影已版本化启用且 readiness=true；否则零扫描。启停即时刷新闸门；成功按批次通知一次。
- 启用态显示目标、暂停原因和停用；各类阻塞均明确提示。
- 合同测试远端调用前要求投影停用，且队列、冲突和投影恢复均为空。
