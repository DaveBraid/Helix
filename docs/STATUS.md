## 本轮目标

- 发布包含滴答首次写入引导、项目任务投影恢复、远端完成状态回写和同步卡顿修复的 Helix `2.1.2`。
- 非目标：不修改用户 Project／Stage／Canvas，不创建或清理滴答对象，不扩大现有远端写入能力。

## 当前事实

- Project／Stage Markdown 是项目身份、状态、正文与本地任务的权威源；专用 Canvas 是关系和布局的权威源。
- Stage 父任务状态直接来自 Stage；父任务完成状态由直属子任务派生，不能手动完成。
- Stage `# 计划行动`进入任务页并形成任意深度本地任务树；未通过滴答写入核验时仍按 Markdown 状态展示。
- 首次启用滴答写入会显示认证与能力核验引导；凭证继续只存于 Obsidian SecretStorage。
- 正向项目投影和反向完成状态复用任务管线、投影账本、CAS 与逐字段冲突机制。
- 滴答清单详情只覆盖活动任务；反向同步会合并普通拉取缓存中的已完成任务，同 ID 以活动详情为准以支持重新打开。
- 父任务冻结只阻止远端写入；身份已验证的子任务状态仍可安全回写 Markdown。远端父任务重新符合 Helix 期望时会清除无待处理记录的幽灵冻结。
- 项目远端同步使用独立串行器，不占用项目工作区 mutation runner；同一项目的多个 Stage 共用一次目标清单目录读取。
- 自动同步候选指纹包含已纳管远端任务状态；普通滴答拉取释放授权锁后会重新计算项目同步条件。
- `2.1.1` 是当前已发布版本；日常开发在 `dev`，本轮已获用户明确发布授权。

## 本轮改动

- `dida-project-projection`：批量复用目录，支持远端完成／重开三方合并、分 Stage 单次 CAS 回写、冻结父任务下的只读子任务对账及幽灵冻结收口。
- `helix-service`：合并清单活动详情与普通同步缓存中的已完成任务，活动详情优先覆盖同 ID 缓存。
- `main`：项目同步使用独立 runner；远端状态加入候选指纹；普通拉取释放授权锁后唤醒项目协调器。
- 设置与本地任务：补齐首次写入引导、能力核验入口，以及未核验时的 Stage／行动任务本地状态展示。
- `manifest.json`、`package.json`、`package-lock.json`、`versions.json`、README 和 `docs/releases/2.1.2.md` 已准备统一发布版本。

## 相关约束

- 权威边界、本地任务投影与滴答合同见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 3、5 节。
- 远端与本地从同一 Base 发生竞争时必须进入逐字段冲突，不允许静默覆盖。
- 合同测试只操作唯一标记的专用临时对象；远端结果未知或清理未证实时禁止盲目重试。
- API 口令只存 SecretStorage；换设备、Vault、授权或合同版本均需重新验证。
- Release 必须包含 BRAT 三个运行文件、第三方声明及完整许可证附件。
