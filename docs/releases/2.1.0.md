# Helix 2.1.0

Helix 2.1 聚焦项目关系图的多项目布局与对齐体验，可从 `2.0.0` 直接升级，不需要迁移 Project／Stage Markdown。

## 项目排序

- Project Lineage 新增“项目排序”菜单，可拖动调整项目顺序。
- 排序写入专用 Canvas 的 `helixProjectOrder` 内部账本，关闭菜单、重载插件或重启 Obsidian 后仍然保留。
- 完整自动布局以该账本作为项目容器的明确排列顺序；旧 Canvas 没有账本时，会按现有容器位置生成兼容顺序。
- 新增推进、分支或合并 Stage 时，局部整理继续服从设定顺序，不会把当前项目移动到队尾；必要时只将排序靠后的容器下移。

## Shift 对齐

- 按住 Shift 拖动时，阶段卡片和项目容器均可吸附对齐。
- 支持水平、垂直以及同层级等间距吸附；阶段与容器互不作为对方的对齐锚点。
- 对齐时显示克制的纯虚线引导；引导仅属于当前交互，不写入 Canvas。
- 容器拖动和排序继续使用 Canvas revision 校验，竞争修改时拒绝覆盖。

## 数据与兼容

- Project／Stage Markdown 与专用 Canvas 的权威边界不变；不复制项目影子数据到 `data.json`。
- 本版本只新增 Canvas 内部排序账本，不改写用户 Markdown 正文、未知 YAML、非托管节点或非托管边。
- 最低版本仍为 Obsidian `1.12.2` 桌面端；不支持移动端。
- 滴答同步能力与 `2.0.0` 相同，升级不会自动开启网络同步或项目投影。

## 已知限制

- 多项目中较早项目因新增复杂分支而扩大时，后续容器会按顺序向下避让；当前不压缩用户主动保留的额外空白。
- 普通滴答子任务的新增、删除和排序仍取决于当前账号已验证的真实合同能力。
- 本地任务暂不支持跨 Stage／项目移动。

## 上游与许可证

- 本版本未引入新的上游实现代码。
- 第三方归属与完整许可证见 Release 附件。
