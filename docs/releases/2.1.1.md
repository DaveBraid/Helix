# Helix 2.1.1

Helix 2.1.1 修复项目关系图在连续新增 Stage 时重排既有卡片的问题，可从 `2.1.0` 直接升级，不需要迁移 Project／Stage Markdown 或 Canvas。

## 增量节点布局

- 新建推进、分支或合并 Stage 时，只为新增节点计算坐标；已有阶段卡片的 Canvas X/Y 不再参与自动整理。
- 推进节点位于父节点右侧并继承父节点 Y；继续延长同一分支时，整条既有链路不再向上压缩。
- 分支仍在同列按稳定行距展开；合并节点仍位于最右父节点下一列，并取全部父节点的平均 Y。
- 项目容器继续按节点外框自适应扩展，不保存第二份容器尺寸真值。

## 未保存布局保护

- 在尚未点击“保存当前布局”时新增 Stage，既有卡片继续保留屏幕上的会话坐标，不会因节点集合变化而恢复到旧 Canvas 坐标。
- 新节点会相对当前显示的父节点落位；连续新增后仍保持父子同行或既定分支行。
- Helix 使用创建前 Canvas Base 逐节点复核；若某个节点确实被外部修改，则采用新的 Canvas 坐标，不以旧会话草稿静默覆盖。
- 布局仍只有在用户点击“保存当前布局”后才写回 Canvas。

## 链路阅读

- 悬停阶段卡片时，当前卡片、全部上游父节点及对应关系线保持突出。
- 后继节点、无关卡片与无关关系线暂时弱化；合并阶段会同时保留所有上游分支。
- 高亮只属于当前视图会话，不写入 Markdown、Canvas 或撤销栈。

## 数据与兼容

- Project／Stage Markdown 与专用 Canvas 的权威边界不变；本版本不迁移用户正文、YAML、非托管节点或非托管边。
- 最低版本仍为 Obsidian `1.12.2` 桌面端；不支持移动端。
- 滴答同步能力与 `2.1.0` 相同，升级不会自动开启网络同步或项目投影。

## 已知限制

- 未保存布局只存在于当前 Helix 视图会话；需要跨 Obsidian 重启保留时，仍应点击“保存当前布局”。
- 普通滴答子任务的新增、删除和排序仍取决于当前账号已验证的真实合同能力。
- 本地任务暂不支持跨 Stage／项目移动。

## 上游与许可证

- 本版本未引入新的上游实现代码。
- 第三方归属与完整许可证见 Release 附件。
