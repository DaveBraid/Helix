## 当前事实

- Project／Stage Markdown 是项目身份、状态、正文与本地任务的权威源；专用 Canvas 是关系和布局的权威源。
- `2.0.0` 已正式发布；`main` 与 `dev` 在本轮开始时同步于 `e6bde81`。
- Stage `# 计划行动`直接进入任务页并形成任意深度本地任务树；编辑使用 Stage revision CAS，不在 `data.json` 保存影子任务。
- 有子任务的本地行动与 Stage 主任务完成状态为派生值：全部直属子任务完成后自动完成，任一子任务重新打开后自动恢复未完成。
- 项目关系图支持推进、分支、合并、关系中插、容器级整理、布局保存读取、项目／阶段改名和颜色编辑。
- 关系图完整自动布局现在以调用方项目顺序作为容器 lane 顺序；Canvas `helixProjectOrder` 是该显式顺序的内部账本。
- 无排序账本的旧 Canvas 按当前阶段容器的上、左位置推导兼容顺序；账本缺少的新项目追加，已删除的旧 ID 忽略。
- 关系图 Shift 吸附独立处理 X、Y 轴与等间距候选；阶段只使用其他可见结构阶段，项目容器只使用其他项目容器，禁止跨层级吸附。
- 新增 Stage 的局部整理只避让排序位于当前项目之前的容器，并在结束时按账本校正全部容器顺序；靠后的项目可下移，当前项目不会被推到队尾。
- 自动同步仍需显式启用；当前测试 Vault 的自动同步为关闭状态。

## 相关约束

- 权威边界、Canvas 排序账本、布局与拖动合同见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 5 节。
- 项目排序必须是当前全部项目的无重复排列；写入绑定打开时 Canvas revision，竞争时零写入拒绝。
- 排序只写内部账本和托管节点坐标，未知 Canvas 字段、非托管节点、Markdown 正文不得改动。
