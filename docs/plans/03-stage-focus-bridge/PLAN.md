# 阶段 3 计划：关系驱动的聚焦问题引用块

## 目标

- 阶段 1 的“本阶段问题聚焦”保持手工填写。
- 后续阶段按 Canvas 入边引用每个前置阶段的“下一阶段聚焦问题”；继承一块，合并多块。
- 关系变更时只重建 Helix 受管引用块，不改其他正文。
- 在目标 Stage 编辑引用内容时，反向 CAS 更新源 Stage 的对应小节，再重新派生所有受影响引用。

## 受管边界

- 使用 Live Preview 中不显示的 HTML 注释标记整个受管包络，每个来源子块包含源 Stage ID 和上次同步哈希。
- 可见内容使用 Markdown callout/引用语法，标明来源阶段和链接；不引入可见 HTML 控件。
- Canvas 边是关系唯一真值，引用块只是派生展示；禁止从普通 blockquote 推断关系。
- 源小节和派生块同时相对上次哈希变化时建立本地冲突，不静默选边。
- 关系变更、源更新、派生反向编辑都走同一串行锁、Markdown 修订 CAS 和 Canvas CAS。

## 分段与安全闸门

- 3A（已完成）：纯 ATX/fence 感知解析、受管包络渲染和仅接收 Canvas 派生 `sourceIds` 的计划函数；损坏、重复、嵌套错位标记一律诊断零写。
- 3B（已完成）：跨文件 CAS 事务、历史镜像与回滚；任一文件竞争冻结，日志只按已知起点／终点恢复。
- 3C（已完成）：仅从 Canvas 托管入边接入关系；断边及删除阶段重派生受管块且不丢用户编辑，Canvas 始终是唯一关系源。
- 3D（已完成）：监听、非权威 Base 检查点、同源多目标协调、持久冲突 UI 与待决恢复事务；自动同步不污染撤销栈，混合未知态冻结工作区。
- 3E（已完成）：在 `ObDevTestVault` 通过 Obsidian CLI 实测 Live Preview 隐藏标记、继承／分支／合并派生、派生块反向编辑、同窗竞争冲突及人工选边；控制台无错误。另修复了权威 Markdown／Canvas 已恢复一致后旧聚焦桥接恢复锁仍永久冻结工作区的问题。CRLF 边界由自动化覆盖，未将其表述为实机编辑器验证。

## 验收

- 首阶段、继承、多源合并、分支、换边、断边、删除源阶段均有纯领域测试。
- 标题同名、空小节、多行引用、嵌套列表、代码块和未知用户内容均不破坏边界。
- 反向修改只更新精确源小节；任一文件竞争时零部分写入或安全回滚。
- Live Preview 不显示隐藏标记，可见引用块可正常编辑，控制台无错。

## 非目标

- 不从引用块创建 Canvas 边，不将聚焦问题同步到滴答。
