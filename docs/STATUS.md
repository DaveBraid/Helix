当前阶段：优化项目任务同步后的本地性能与任务层级体验；暂不发布、不合并主分支。

## 本轮目标

- 消除 Stage Markdown 编辑和 Helix 启动／切页时的重复全库扫描与同步锁等待；按真实父子关系展示项目任务。
- 非目标：本轮不修改真实滴答对象、不重新运行写入合同、不调整项目同步语义或发布版本。

## 当前事实

- Project／Stage Markdown 与专用 Canvas 是项目权威源；`data.json` 只保存恢复、同步与事件状态。
- 状态为“进行中”的 Stage 对应 `Helix Projects` 清单中的远端父任务；`# 计划行动`对应真实 `parentId` 子任务，远端备注不写 Helix 标记。
- 本地计划行动与子任务直接从 Stage Markdown 投影到任务页，不建立第二份任务存储；本地编辑使用 Stage revision CAS。
- 任务页列表按真实 `parentId` 缩进，已完成任务在同级稳定下移；“进行中”筛选包含进行中 Stage 父任务及其后代。
- 滴答普通同步、项目任务同步、离线队列、写门和冲突合并仍共用一套 `HelixService` 管线。
- 项目派生缓存只保存可由 Markdown／Canvas 重建的内存视图，不是权威数据，也不进入 `data.json`。
- 版本仍为 `1.0.1`，最低 Obsidian `1.12.2`。

## 本轮改动

- 项目启动和受管文件刷新各只读取一次稳定工作区快照，并复用于 Canvas 派生修复、本地任务投影和聚焦冲突计数。
- Helix 页面渲染改为只读内存缓存，不再补写任务身份，也不再等待后台项目远端同步持有的全局串行锁。
- 新增共享任务树投影：完成项稳定后置、真实父子缩进、筛选父任务时自动包含后代；Stage 父任务通过 Markdown 中的精确远端 ID 识别。
- 任务页新增“隐藏／显示已完成”按钮；含子任务的滴答任务详情复用 Dense Helix 详情框架显示进度环和子任务列表。
- 架构文档已记录缓存失效边界和任务树唯一逻辑，避免各视图复制排序／层级算法。

## 相关约束

- 权威源、同步写门、未知结果和项目任务规则见 [ARCHITECTURE.md](ARCHITECTURE.md)。
- 缓存失效后必须从权威文件重建；渲染路径禁止改写 Markdown 或持久化影子任务。
- 凭证只存 SecretStorage；远端结果未知禁止重发，冲突禁止静默覆盖。
- 真实写入和清理只能使用精确 ID 与 Helix 专用对象；不得触碰用户既有任务和清单。
