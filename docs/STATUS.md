## 当前事实

- Project／Stage Markdown 是项目身份、状态、正文与本地任务的权威源；专用 Canvas 是关系和布局的权威源。
- main 的 Shift 同轴吸附、容器级整理、布局保存读取、关系中插、阶段编号维护、项目颜色编辑和单箭头悬停加号均已保留。
- Stage `# 计划行动`直接进入任务页，缩进项形成任意深度本地任务树；编辑使用 Stage revision CAS，不在 `data.json` 保存影子任务。
- 有子任务的本地行动与 Stage 主任务完成状态均为派生值：全部直属子任务完成后自动完成，任一子任务重新打开后自动恢复未完成；终止不计为完成。
- 派生主任务的完成圆只读，详情状态中的“已完成”不可主动选择；叶任务仍可直接完成或重新打开。
- 多层父子树在一次 Stage Markdown CAS 内自底向上定点收敛；启动、受管文件刷新及任务增删改都会校正父任务与 Stage 状态。
- 任务树父节点使用 44px 环形进度／完成勾，叶节点使用 24px 完成圆；折叠入口位于右侧，子级缩进为 18px。
- 普通滴答任务、Stage 行动和项目投影父任务共用统一任务详情页；项目投影复用 `HelixService`、唯一离线队列、共享远端写门和冲突管线。
- 自动同步和项目投影仍需显式配置与运行时 readiness；当前测试 Vault 的自动同步为关闭状态。
- `manifest.json`、`package.json`、`package-lock.json` 与 `versions.json` 已统一为 `2.0.0`，最低 Obsidian `1.12.2`。
