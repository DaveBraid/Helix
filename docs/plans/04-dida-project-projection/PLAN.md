# 阶段 4 计划：Helix 项目向滴答的单向投影

## 目标

- 一个 Helix Project 投影为滴答“科研”清单中“Helix项目”看板列的一个父任务。
- Stage `# 计划行动` 下的受管 Markdown 任务投影为对应项目父任务的子任务。
- 只实现 Helix → 滴答；滴答变更不反写 Markdown，但写前/写后仍精确复读以防覆盖竞争。
- 复用现有 Helix 任务正规化、写入队列、授权合同、父子能力、看板归栏、未知结果和冲突管线；禁止建第二套同步引擎。

## 4A 当前进度

- 已完成领域与共享同步管线接入：Project/Stage Markdown 仍是身份和行动真值，投影写入统一经过 `HelixService → OfflineQueue → RemoteWriteGate → SyncEngine`。
- 创建操作在发出远端请求前持久化命名空间化 `clientIdentity` 和操作 ID；进程在 `running` 中断后恢复为结果未知，禁止重发。
- 投影状态、父任务检查点、行动账本和操作收据已接入严格持久化端口；它们只用于恢复和冻结，不保存完整滴答任务，也不替代 Markdown 或远端事实。
- `verified` 收据只可凭匹配清单、远端 ID 与唯一标记的 Base 快照恢复；缺失或身份不符统一返回冲突，由投影层持久冻结。
- 写入合同版本 6 在既有任务能力之外增加唯一标记分栏的双源创建验证，并继续使用独立临时任务验证“完成 → 最小 `status=0` → 精确复读”；能力均绑定当前授权，测试对象未安全清理时保持只读。
- 已补自动化覆盖：重启零重复发送、普通／投影并发仍为单消费者、Base 收据恢复、身份错配冻结、未验证重开零入队及最小状态载荷白名单。
- 4A 不启用设置或项目页入口，不选择生产清单／列，不对用户现有滴答对象执行写入；生产激活属于后续显式验收动作。

## 4B1 当前进度

- 已接入 Vault Markdown、现有任务管线、持久投影状态、远端目录和冲突诊断适配器；`didaProjectionState` 是唯一配置源。
- 已提供项目读模型、未加入行动显式加入、标题／五状态 CAS 编辑、精确激活／禁用、后台自动同步和冻结复核的窄应用接口。
- 已在任何远端副作用前全局校验 UUID／marker 归属，并复用同一 Stage revision 消除 TOCTOU；冻结 tombstone 作为孤儿诊断可在重启后发现和严格复核。
- 结果未知解冻与收据清理 proof 同步持久化；纯读不触发清理，启动与显式入口可幂等重试。
- 4B1 仍默认关闭，无 UI、无自动同步、无真实滴答写入；4B2 才开放显式用户入口。

## 4B2 完成状态：显式用户入口

1. 设置页增加常规“项目投影”区：精确选择远端清单／已有分栏，展示稳定 ID、能力与数量预览；同入口二次确认激活，显式禁用，不创建分栏。
2. 项目页以同步工作区替换旧映射条：展示父任务、已加入／未加入／失联／冻结／待清理汇总；按阶段加入、CAS 编辑；显式启用后由 Project／Stage／Canvas 变更防抖唤醒后台同步。
3. 冲突中心增加投影诊断组：pending 显式重试，孤儿／冻结严格按 project+stage+uuid 复核；普通收据只调用安全清理，不提供旁路删除。
4. UI 使用纯 presenter/coordinator 生成状态与动作资格；所有异步入口以 render token 和按钮禁用防重复，中文文案、键盘可达及暗色变量统一落入现有设计系统。
5. 只做伪远端与结构／交互／CSS 自动化验证；保持默认关闭、无自动投影、无真实滴答写入，分栏创建留到 4C。

基础投影曾经看门狗审查通过：设置页精确目录与同入口双确认、项目页行动面板、冲突页安全收口组及纯 presenter 已接入；当前新增自动协调器仍默认关闭，启用后也只复用既有队列、写门与冲突收口。自动化通过不代表 Obsidian 实机 UI 或真实滴答同步已验收。

## 4C 完成状态：显式安全创建缺失分栏

1. 写入合同在自己的唯一临时清单内始终创建并从项目详情与分栏端点双源精确复读一个唯一标记分栏；临时清单仍按既有稳定身份整体安全删除，不单独删除或改名任何列。只有完整验证且临时对象无残留时，才为当前授权发布 `columnCreateVerified`。
2. `didaProjectionState` 只增加非权威、无凭证的列创建 checkpoint：固定目标名称 `Helix项目`，保存 operationId、目标清单 ID、列基线摘要／哈希、确认 previewHash、prepared/running/unknown 状态、可选远端列 ID 与错误摘要；所有字段严格校验并 CAS 持久化。
3. 设置页仅在精确清单内不存在同名列时展示“创建分栏”预览；预览包含清单名与稳定 ID、完整列基线摘要，以及能力、授权、队列和 unknown blockers。同一入口二次确认，确认前重新双源读取并验证预览哈希。
4. 完整确认事务独占现有 `remoteWriteGate`；fresh 双源预览、checkpoint、单发 `createColumn`、写后双源复读与清 checkpoint 期间，普通同步、合同测试和口令切换不能并发。
5. `prepared` 证明请求未发送：重启时安全清除，prepared→running 持久失败也清除并返回原错误。只有持久化为 running 后的中断或远端结果不明才冻结 unknown，绝不自动重发。冲突中心显式复核时，有 remoteColumnId 则精确匹配；无 ID 仅领养相对基线唯一新增且名称精确为 `Helix项目` 的列；多候选或其他竞争保持冻结。
6. 创建与复核永不删除、改名或重排任何列；同名已存在、能力过期、队列非空、授权变化、unknown 未收口和基线变化均在远端写入前阻断。复用现有目录双源读取、授权能力绑定和远端写门，不建立第二任务或同步引擎。
7. 自动化覆盖合同能力绑定、checkpoint validator、二次点击、预览哈希变化、同名列、能力过期、并发列变化、崩溃窗口、重启显式复核与多候选冻结；本阶段只对合同专用临时清单产生真实写入，生产列创建必须由用户明确确认。

代码已完成并经看门狗审查通过，合同版本升级为 v6；尚未通过当前 Obsidian 进程的 CLI 实机验收，也尚未运行真实 v6 专用临时清单合同，因此不得宣称真实分栏创建或生产投影通过。

## 4D 子计划：真实合同残留的可恢复安全清理

已完成：核心实现提交于 `e03c8ca`，Electron 二次确认计时器热修提交于 `f77f78d`。全量 63 个测试文件／775 项及发布门禁通过；Obsidian CLI 重载后双确认武装正常。显式只读领养精确识别 2 个专用清单／1 个专用任务，随后双确认精确清理完成；本地 pending 与 recovery 均为 0，远端合同命名清单只读计数为 0，开发错误与控制台错误为 0，调试已关闭。本次没有运行新合同，也未触碰普通滴答或 Obsidian 用户数据。以上只证明 4D 合同残留收口，不代表生产项目投影或生产分栏已经配置、启用或验收。

1. 合同报告增加仅供内部持久恢复使用的 `cleanupPlan`，逐项记录本轮 run 身份、已跟踪临时清单的稳定 ID／精确名称／完整列基线，以及任务稳定 ID、候选清单与 open/completed/unknown 状态；不得进入 Notice 或普通诊断。
2. 合同非清洁结束时把严格校验的 plan 写入 `pendingDidaContractCleanup`，成功清洁时清除；存在 pending 时禁止开始新合同。每个已证明不存在的对象都以 CAS 从 plan 移除，支持进程中断后继续。
3. 恢复全程独占远端门。先在候选清单中有界只读定位任务，只有唯一位置且 ID／marker 精确匹配才单发删除；删除响应未知时只读复读，证明仍存在则保持 unknown 且永久禁止再次删除。所有任务证明清理后，临时清单还须精确匹配 ID、名称、双源完整列基线和空任务集，才单发删除并复读集合不存在。
4. 旧版未持久 plan 的本轮残留只能由显式领养入口处理：远端合同命名格式必须恰好一个 run 组，A/B 各一、无第三项目或歧义，所有可见任务均带同一 marker；列基线从当前双源一致集合收养并标为 adopted。多个 run 组一律拒绝。
5. 查询限流只按服务端 retryAfter 做有界只读等待；未知结果、竞争、定位歧义或清理证据不足均保留 plan，不猜测、不重发、不删除普通对象。冲突中心只显示脱敏计数和状态，并以双确认开放“严格领养”或“冷却后精确清理”。

## 配置与身份

- 设置保存精确的目标滴答清单 ID 和目标列 ID；“科研”和“Helix项目”仅作首次配置建议，不在同名或身份不明时自动选择。
- 开启前展示精确清单、列和将创建的对象；没有列时只在用户显式启用后单发创建“Helix项目”，不修改其他列。
- Project Markdown 只保存已复读的滴答父任务 ID；每条计划行动通过 Live Preview 隐藏的受管 HTML 注释保存本地 UUID、状态和已复读子任务 ID。
- `data.json` 只保存队列、Base/Local/Remote 快照和未知结果状态，不成为项目或行动映射真值。

## 增删改合同

- 增：Markdown 先 CAS 分配本地 UUID；只发一次创建，写后精确复读 ID/父级/清单/列/标题，再 CAS 回填远程 ID。回填竞争进入人工关联，不重发创建。
- 改：只从 Markdown 受管行动生成字段意图，复用现有任务更新白名单、写前复查与写后验证。
- 状态：`completed` 映射滴答完成；`idea/active/paused/terminated` 在滴答均保持开放，其 Helix 状态不伪装成滴答原生状态。终止是 Helix 语义，不自动完成或删除远程任务。
- 删：删除受管行动会产生持久 tombstone；仅在子任务 ID、父任务 ID、目标清单与唯一标记全部复读一致时删除。远程结果未知时冻结 tombstone 并人工核对，不重发。
- Project 文件或阶段文件删除不级联删除滴答清单、列或其他用户任务。

## 验收与真实测试边界

- 先用伪远程覆盖增删改、父子映射、列归属、授权过期、冲突、CAS 竞争、网络中断和重启恢复。
- 真实合同只使用 Helix 唯一标记的临时清单/列/父子任务，精确清理；不在“科研”清单调试。

- 待写队列非空、能力合同过期、目标看板过期或有残留未知时禁止激活。
