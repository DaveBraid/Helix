## 本轮目标

- 新建 Stage Markdown 直接使用完整一级标题作为文件名，例如 `阶段 3 · 123.md`。
- 界面或 Markdown 双向修改阶段名后，按稳定身份同步修改文件名。
- 精确迁移既有 `Stage-XX.md`，文件内容逐字节不变。

## 当前实现

- Stage 身份由唯一 `helix-id` 确定，`helix-project-id` 校验归属；路径只作当前索引，哈希只作 CAS 版本比较。
- 创建阶段时以完整一级标题生成文件名；非法文件名字符被安全替换，UTF-8 文件名超过 240 字节时解释性拒绝。
- 启动和项目刷新会核对 Stage 一级标题与当前路径。旧文件迁移前复核身份、Markdown 哈希、Canvas 哈希、目标占用和目标冲突；移动后验证内容与哈希未变，再更新 Canvas 派生路径。
- Canvas 提交失败会按原哈希逆序回滚已移动文件；回滚再竞争时冻结项目工作区，禁止猜测覆盖。
- 界面重命名继续只修改既有托管标题和属性，并同步移动 Stage 文件；撤销和重做会按稳定 ID 重绑新路径。
- 聚焦桥接 checkpoint／conflict 的路径缓存按稳定 Stage ID 更新；纯路径迁移保持 Markdown 原文不变，后续显式改名或来源正文变化时才以 Markdown 外的旧展示哈希安全重绘。旧 `Stage/Cycle-XX` 与 WikiLink 有无 `.md` 后缀均做精确 canonical 兼容，伪造 marker 哈希不能授权覆盖。
- 会改变 Stage 一级标题的结构写入、撤销和重做统一在历史日志前预检并移动文件；目标占用保持历史栈与内容原状，日志建立后的失败继续由既有恢复协议接管。
