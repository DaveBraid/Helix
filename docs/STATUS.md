## 当前事实

- Project／Stage Markdown 是项目内容权威源，专用 Canvas 保存关系与布局；`data.json` 只保存恢复和同步状态。
- Stage `# 计划行动` 顶层条目进入任务页，缩进条目为本地子任务；任务页已移除“项目关联任务”板块。
- 滴答读取、普通写入、合同与项目同步共用 `HelixService`、持久队列、远端写门和单一消费者。
- 当前授权 v13 已证明普通任务 CRUD、完成／重开、真实父子关系和项目同步合同；能力绑定当前口令。
- 一个已纳入同步的 Stage 对应一个远端父任务；计划行动对应带真实 `parentId` 的普通子任务。Helix Project 本身不创建远端任务。
- 项目任务目标使用精确远端清单 ID；远端父子任务 `content` 为空，内部身份只保存在 Markdown、账本、操作 ID 和收据中。
- 自动目标准备与项目任务写入跟随普通“自动同步”总开关；关闭时扫描和写入 readiness 均停止。
- 版本仍为 `1.0.1`，最低 Obsidian `1.12.2`。

## 本轮改动

- 自动目标由单数 `Helix Project`＋专用分栏改为复数 `Helix Projects` 清单根级任务；激活语义版本升为 3。
- 创建与更新不发送 `columnId`；不创建看板或分栏；清除新旧父子任务的可见 `content` 标记。
- Stage 输入新增 `createWhenMissing`：仅“进行中”为 true；非进行中且无绑定时零写入，已有绑定仍可更新或完成。
- 取消对看板归栏／分栏创建能力的项目同步前置要求；保留普通看板功能本身的独立门禁。
- 取消 marker／分栏作为恢复身份，改用既有收据中的精确远端 ID、清单 ID、父任务 ID 与字段复读；无 ID 时保持冻结，禁止按标题领养。
- 已验证删除会清除同一远端任务的旧 create/update 收据，避免已不存在的对象永久占用 `clientIdentity`；markerless v3 收据只允许已知内部身份前缀。
- 完成／重开写入使用刚刚精确复读的 Fresh Base，避免滴答派生 `childIds` 与创建时旧 Base 形成伪冲突。
- 测试 Vault 已关闭自动同步，并通过旧版安全删除管线清除单数清单中的 8 个阶段父任务和 4 个行动子任务；队列、冲突、恢复项均为 0。空的单数 `Helix Project` 清单随后按精确 ID 删除，复数 `Helix Projects` 及其既有任务未修改。
