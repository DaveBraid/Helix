# Helix 2.1.3

Helix 2.1.3 改进项目／阶段状态表达，并修复 Stage 计划行动在 Helix 与滴答中的顺序一致性。可从 `2.1.2` 直接升级。

## 项目与阶段状态

- 关系图项目容器和顶部横排选单中，项目状态现在使用统一的图标与颜色。
- 阶段状态“想法”显示为“计划中”，图标和颜色保持不变。
- 新增“待记录”阶段状态。所有根计划行动完成后自动进入待记录；“已完成”仍由用户手动确认。

## 计划行动顺序

- 同一 Stage 批量生成滴答子任务时，滴答最终展示顺序与 Stage Markdown 行序一致。
- Helix 任务树对已绑定行动恢复 Markdown 同父行序，普通滴答任务和 Stage 根父任务位置不变。
- 本修复不写入远端 `sortOrder`，也不修改 Stage Markdown 任务顺序。

## 项目投影恢复

- 自动同步开启后，当前版本的停用配置可按稳定清单 ID 安全原位恢复，不因清单改名创建第二目标。
- 单个 Stage 的冲突只冻结自身，其他 Stage 继续同步。旧版、换目标或身份不完整的配置仍拒绝自动恢复。

## 迁移与数据边界

- Project／Stage Markdown 和专用 Canvas 的权威边界不变；除下述 Helix 管理 marker 位置收口外，本版本不迁移用户正文、未知 YAML、非托管节点或非托管边。
- 若历史行动存在“合法 Helix marker 后跟可见文本”，启动收口只把 marker 移到行尾，可见文本原样保留；损坏 marker 不会被推断修复。
- 口令继续只存于 Obsidian SecretStorage；非权威的投影配置与恢复身份保存在当前 Vault 的 `.obsidian/plugins/helix-productivity/data.json`，不保存项目或阶段影子真值。
- 最低版本仍为 Obsidian `1.12.2` 桌面端；不支持移动端。

## 已知限制

- Stage 之间的任务移动仍未开放。
- 既有投影冲突仍需在冲突中心逐项收口；不会为了继续同步而静默覆盖。
- 离线创建超时仍属于远端结果未知，必须人工确认，不能盲目重试。

## 上游与许可证

- 本版本未引入新的上游实现代码。
- 第三方归属与完整许可证见 Release 附件。
