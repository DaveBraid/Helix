# Helix 2.0.0

Helix 2.0 将本地项目工作流、递归任务树与经过合同验证的滴答同步能力合并为同一正式基线，兼容 `1.0.2` 的现有 Markdown、Canvas 与 SecretStorage 凭证。

## 项目与本地任务

- Stage `# 计划行动`直接进入任务页，缩进清单项形成任意深度的本地父子任务树。
- 主任务完成状态由直属子任务自动驱动：全部完成后自动完成，任一子任务重新打开后自动恢复未完成；不能从完成圆或详情属性手动绕过。
- 统一任务详情页支持标题、状态、优先级、日期、时间、标签和子任务编辑，并使用 Stage revision／CAS 防止竞争覆盖。
- 项目关系图保留 Shift 对齐、容器级整理、布局保存与读取、关系中插、阶段编号维护、项目颜色和箭头悬停插入。

## 滴答同步

- 开放滴答清单与普通任务读取、编辑、完成、重开及安全队列同步。
- 开放 Helix Project→滴答的后台单向投影：进行中的 Stage 对应滴答父任务，计划行动对应真实子任务。
- 项目投影复用普通任务的唯一离线队列、共享远端写门、写前复读、写后验证和逐字段冲突流程，不建立第二套同步引擎。
- 自动同步默认关闭；项目投影还要求当前版本合同能力有效并由用户单独确认，升级不会静默启用远端写入。
- 远端结果未知时冻结对应对象，禁止盲目重试；其他任务可继续同步。

## 数据与升级

- 可直接从 `1.0.2` 升级，无需破坏性迁移。
- Project／Stage Markdown 与专用 Canvas 仍是项目数据唯一真值；`data.json` 不保存项目影子数据。
- 不覆盖未知 YAML、用户正文、模板、非托管 Canvas 内容或未确认的远端冲突。
- API 口令继续只存于 Obsidian SecretStorage，不进入仓库、日志或 Markdown。

## 已知限制

- 项目同步当前以 Helix→滴答单向投影为主；滴答侧竞争修改进入冲突流程，不自动反向覆盖 Markdown。
- 普通滴答子任务的新增、删除和排序仍取决于当前账号已验证的真实合同能力。
- 本地任务暂不支持跨 Stage／项目移动。
- 仅支持 Obsidian `1.12.2` 及以上桌面端，不支持移动端。

## 上游与许可证

- 本版本未引入新的上游实现代码。
- 第三方归属与完整许可证见 Release 附件。
