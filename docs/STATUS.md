## 本轮目标

- 在不触碰用户既有滴答对象和正式 Vault 的前提下，依次验证只读、专用写入合同、普通任务同步、恢复机制及项目单向同步。

## 当前事实

- Project／Stage Markdown 是项目内容权威源，专用 Canvas 保存关系及布局；`data.json` 只保存恢复与同步状态。
- Stage `# 计划行动` 顶层条目进入 Helix 任务页；缩进条目为本地子任务。
- 滴答能力分为只读、普通任务写入、专用合同和项目同步四层；前三层代码开放，项目同步由独立发布门禁硬关闭。
- 普通任务 CRUD、跨清单移动、完成／重开、逐字段冲突、重启队列和真实父子关系已有自动化与真实合同证据。
- 项目父级映射为带稳定 marker 的普通滴答 Task；Stage 行动映射为带稳定 `parentId` 和 marker 的普通子 Task，不使用父任务 `items`。
- v11 合同要求 `projectProjectionVerified` 同时覆盖正式项目同步编排器和生产 `OfflineQueue→queueDrain→写后收据` 创建／删除闭环。
- 远端结果未知禁止重发；同字段竞争保留 Base／Local／Remote 并逐字段人工选择。
- 版本 `1.0.1`，最低 Obsidian `1.12.2`；本阶段不发布。

## 本轮改动

- v11 合同主体预算 190，安全清理独立保留 40 次；旧能力缓存按设计失效。
- 临时父子任务先进入持久清理计划，再允许合同继续验证。
- 项目行动属性更新与完成／重开拆成独立意图，状态变化调用正式 `completeTask`／`reopenTask`，不再误用普通更新载荷。
- 日期复读按公开接口的秒级时间语义比较；失败诊断只报告字段名，不泄露对象内容或身份。
- 项目合同删除与生产任务删除统一以清单开放任务集合为权威；详情端点短暂返回旧对象不再误报失败。
- 新增合同排他锁内的生产队列探针；只临时允许本轮唯一队列操作，不改变 `PROJECT_DIDA_PROJECTION_AVAILABLE=false`。
- 修复项目任务创建的分栏派生字段验证、无父级 `null`／缺失等价和删除 Base 错带 `columnId` 导致的假冲突。
- 旧 items 队列、冲突和账本继续永久只读隔离；项目同步发布门禁仍为关闭。
- 合同队列删除写前复读已纳入同一预算 API；投影远端结果未知会冻结为 reconciliation 且不再发送，同字段竞争会阻塞并生成逐字段冲突，均有生产队列回归。
- 设置页只读取选中的滴答清单，支持选择既有分栏或经预览和二次确认创建 `Helix项目` 分栏；启用也要求预览后二次确认，停用不删除远端对象。
- 项目投影激活新增版本凭证；历史无凭证 enabled 状态加载后自动降为禁用，保留映射与诊断但禁止升级即写。
